# 提问模式 · 人工验收清单

状态：待执行 · 最后核对日期：2026-10-13

自动化已经覆盖的部分不在这里重复。本清单只列**必须在真实浏览器 + 真实 WebRTC 会话里走一遍**的项，
对应 `openspec/changes/add-quiz-mode/tasks.md` 的 8.3、8.4、10.1、10.2、10.3、10.8。

> 为什么要人工：这些验收依赖真实麦克风、真实 WebRTC 会话和数字人朗读，
> 单元测试用的是假 speaker 与替身录音，覆盖不到。

---

## 0. 前置准备

```bash
# 启动（端口 8010）
python app.py --transport webrtc --model wav2lip --avatar_id 123
# 或用 start.bat
```

1. 浏览器打开 <http://127.0.0.1:8010>，点「开始连接」，页面上的 **SID: xxx** 就是 `sessionid`，记下来。
2. 准备讲稿：在「预设文本」里写 4～6 段，每段前插 `[PPT:N]` 标签（用上方 PPT 选择器插入）。
   例：`[PPT:1]今天我们讲铁路客流统计。[PPT:2]先看统计口径。……`
3. 准备题库：至少 3 道题。可以先点题库生成，或直接用 `GET /api/quiz/bank` 看现有题目。

**全程用这两个命令观察状态**（课堂面接口，不需要口令）：

```bash
curl "http://127.0.0.1:8010/api/quiz/status?sessionid=<SID>"
curl "http://127.0.0.1:8010/api/quiz/records?sessionid=<SID>"
```

`stage` 的取值顺序应为：`teaching → asking → awaiting_answer → feedback → teaching → … → finished`。

## T1 · 普通模式回归（任务 10.1）

**目的**：不启用提问模式时，行为必须和改动前完全一致。

- [ ] 不勾选「启用提问模式」，直接播报预设文本
- [ ] 记录 `/api/current_slide` 的取值序列（切页时机），播报过程中反复执行：
      ```bash
      curl "http://127.0.0.1:8010/api/current_slide?sessionid=<SID>"
      ```
- [ ] 确认首页**没有**出现提问卡片（DOM 里查不到 `.quiz-card`）
- [ ] 确认讲课从头到尾连续，没有停顿等作答

**判定**：与改动前一致——连续讲授、切页时机不变、页面上没有提问相关元素。

---

## T2 · 提问模式端到端（任务 10.2 / 8.4）

**目的**：完整走一遍「提问 → 作答 → 判分 → 反馈 → 继续讲」。

- [ ] 勾选「启用提问模式」，数量填 `3`，方式选「随机抽取」，页码范围留空（或填 `1-6`）
- [ ] 点「开始提问式讲课」
- [ ] 讲到提问点后数字人停下，**屏幕上弹出提问卡片**
- [ ] 卡片上确认能看到：**题干**、**进度（已完成 N/3）**、作答输入框、语音作答按钮
- [ ] 用**文字**作答并提交 → 数字人朗读反馈
- [ ] 反馈朗读期间**卡片仍在屏幕上**，并显示判分结果与反馈语（不是一提交就消失）
- [ ] 反馈结束后继续讲下一段，卡片消失
- [ ] 至少有一次用**跳过本题**，确认能继续往下讲
- [ ] 3 处提问全部走完，课堂正常结束
- [ ] 结束后查 `/api/quiz/records?sessionid=<SID>`：**有 3 条记录**，
      每条含 `question_id` / `answer` / `verdict` / `feedback` / `degraded` / `unanswered`

**判定**：3 条记录完整，`feedback` 字段**不是空字符串**（这是本轮新补的落库字段，
如果为空说明 `add_record` 没传 feedback，是个真 bug）。

## T3 · 语音作答成功（任务 8.3）

- [ ] 走到一个提问点，点「语音作答」→ 按钮变成「停止录音」
- [ ] 对着麦克风**清楚地说**一句回答（建议 3～5 秒，别太短）
- [ ] 再点一次停止 → 自动上传
- [ ] 卡片上显示**识别结果文本**（确认机器听到的和你说的一致）
- [ ] 随后正常判分、朗读反馈

**重点关注**：识别结果必须是**简体中文**。如果出现繁体字，说明 `initial_prompt` 没生效。
另外留意首字延迟——首次转写要加载模型（约 1.2–3.0 秒），之后会快很多。

---

## T4 · 语音转写失败后可重录（任务 8.3）

**怎么造失败**：在一个安静的环境里录**一段纯静音**（不说话，录 2～3 秒后停止）。
服务端会返回「未识别到语音」。

- [ ] 提交后弹出提示，文案里应含**「可以重新录制一次」**
- [ ] **作答状态保留**——卡片还在，输入框还能用，没有被判成未作答
- [ ] 重新录一段有声音的回答 → 这次正常提交成功
- [ ] 查 `/api/quiz/records`：本题只有**一条**记录（不是失败一次就记一条）

**判定**：失败不推进课堂，也不污染记录。

---

## T5 · 判分降级（任务 10.3）

**怎么造失败**：打开 <http://127.0.0.1:8010/settings.html>，把 LLM 的 `base_url`
改成一个无效地址（例如 `http://127.0.0.1:9/v1`），保存。

- [ ] 走一次提问并作答
- [ ] 数字人**没有卡住**，而是说一句类似「这个问题我先记下来，我们继续往下讲。」的过渡语
- [ ] 课堂继续往下讲，不会停在等待作答状态
- [ ] 查 `/api/quiz/records`：该条记录 `degraded` 为 **true**

**判定**：判分挂了不影响课堂推进。测完记得把 LLM 配置改回去。

---

## T6 · 精确绑定（任务 10.8）

**目的**：幻灯片 3 必须问指定的那道题。前端目前没有暴露绑定配置，用命令行发。

```bash
# 先看题库里有哪些题
curl "http://127.0.0.1:8010/api/quiz/bank"

# 发起，把 <QID> 绑到幻灯片 3
curl -X POST "http://127.0.0.1:8010/api/quiz/lecture" \
  -H "Content-Type: application/json" \
  -d '{
        "sessionid": "<SID>",
        "text": "[PPT:1]第一段。[PPT:2]第二段。[PPT:3]第三段。",
        "count": 2,
        "mode": "random",
        "bindings": {"3": "<QID>"}
      }'
```

- [ ] 返回体里 `assignments` 中，幻灯片 3 对应的提问点绑定的就是 `<QID>`
- [ ] 课堂走到幻灯片 3 时，问的确实是那道题
- [ ] 走完问答后查 `/api/quiz/records`：该提问点的 `question_id` **与 `<QID>` 完全一致**

**判定**：绑定表与最终记录逐项对得上。

## T7 · 直接填问答对 / 纯提问（任务 11.x）

目标：确认**不写讲稿也能提问**，且问答对按你填写的顺序问。

**T7a · 边讲边问**

- [ ] 在「预设文本」里写好带 `[PPT:N]` 的讲稿；在「提问模式」卡片里点「添加一对」，填 **2 对**问答对（题目 + 参考答案），**数量字段随便填 `5`**
- [ ] 点「开始提问式讲课」：返回体里 `total` 必须是 **2**（数量字段被忽略），`question_ids` 形如 `inline-1`、`inline-2`
- [ ] 先讲一段，再问第 1 对；答完（或跳过）后继续，再问第 2 对——**顺序与填写顺序一致**
- [ ] 给其中一对填**页码**（如 `2`）：确认该题在**念题干时**切到第 2 页（不是投喂时刻）

**T7b · 纯提问（无讲稿）**

- [ ] 把「预设文本」**清空**，只留 2 对问答对，点「开始提问式讲课」
- [ ] 数字人**不朗读任何讲稿**，直接念第 1 题题干 → 作答 → 念反馈 → 念第 2 题 → 作答 → `stage` 变为 `finished`
- [ ] 查 `/api/quiz/records?sessionid=<SID>`：**2 条记录**，`question_id` 为 `inline-1`、`inline-2`，且 `feedback` 非空

**T7c · 报错路径**

- [ ] 只填题目、不填参考答案 → 点开始时提示「第 N 对问答缺参考答案」，**没有**发出请求（浏览器 Network 里看不到 `/api/quiz/lecture`）
- [ ] 两对填同一个页码 → 启动被拒，报错里指出该页码是哪一对

**判定**：纯提问模式下讲稿确实没被朗读；记录里 `question_id` 顺序为 `inline-1`、`inline-2`。

## 需要你记录并反馈的内容

每走完一项，麻烦记下：

1. **实际观察到的 `stage` 序列**（从 status 接口抓）
2. **`/api/quiz/records` 的最终 JSON**（这个最有价值，能直接看出判分、降级、反馈落库对不对）
3. 任何**与预期不符**的地方，尤其是：
   - 提问卡片该出现时没出现 / 不该出现时出现了
   - 反馈语是空的
   - 识别结果是繁体
   - 课堂卡住不动

## 已知未覆盖（不要当成 bug）

- GPU 转写：本机缺 `cublas64_12.dll`，`STT_DEVICE=cuda` 走不通，这是已知且**故意不做**的（见 design.md 决策）。
- 真实浏览器会话里的完整闭环，在本次走查之前**从未跑过**——它由 32 个编排测试 + 42 个接口测试 + 19 个前端测试覆盖，但都用替身。
  所以本清单就是补上这个缺口的，发现问题属于正常预期。
