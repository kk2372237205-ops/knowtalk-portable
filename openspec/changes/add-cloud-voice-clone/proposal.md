# 参考音频可作为在线音色使用（云端声音复刻）

## 为什么

用户希望数字人用「指定人物的声音」说话，并且速度和原来的在线音色一样。
现状有三层障碍：

1. **原来的在线引擎已经失效**。`edge-tts` 7.2.8 被微软以 **403** 拒绝握手，
   三个常用音色全部失败；由于默认备用引擎是 `sapi`，实际听到的是 Windows
   系统语音（机械音）。升级到 7.3.1 后恢复正常，首包 1.6–3.0 秒。

2. **EdgeTTS 协议上不可能接受音频文件**。`tts/edge.py` 的
   `_is_edgetts_voice()` 只能识别微软音色名，传入路径会被静默替换成默认音色。
   也就是说「把参考音频当音色」在 Edge 引擎下无论怎么配置都做不到。

3. **豆包引擎虽然已内置，但跑不起来**，有三处硬缺陷：

   | 位置 | 现象 | 真实原因 |
   | --- | --- | --- |
   | `tts/doubao.py` 连接 | 一调用就 `TypeError` | 用的是 `extra_headers`，而 websockets 16.1.1 已改名为 `additional_headers`，两个名字不共存 |
   | `desktop_app.py` 高级设置 | 引擎下拉里没有 `doubao` | 界面硬编码了 6 个引擎，与 `settings_store.TTS_ENGINES`（10 个）不一致 |
   | `desktop_app.py` 参考音色 | 手填 `S_xxx` 被丢弃 | 下拉是 `readonly` 且 `_ref_value()` 查不到标签映射就返回空串 |

   第三条最隐蔽：即使前两条都修好，用户选了复刻音色也会被静默换成默认音色，
   表现为「配了没效果」。

## 做什么

1. **集群自动推断**：复刻音色的 speaker_id 形如 `S_xxxxxxxx`，与标准音色
   （`zh_female_xxx`）走不同集群。`tts/doubao.py` 按前缀推断
   `volcano_icl` / `volcano_tts`，并允许 `DOUBAO_CLUSTER` 强制覆盖；
   复刻音色额外开启 `split_sentence=1`（官方建议，缓解复刻音色语速偏快）。

2. **websockets 跨版本兼容**：启动时探测 `connect()` 签名，自动选用
   `additional_headers` 或 `extra_headers`。

3. **界面与后端同源**：高级设置的引擎/备用引擎下拉改为引用
   `TTS_ENGINES`，不再各写一份。

4. **参考音色支持手填**：主设置页与高级设置的下拉改为可输入；
   `_ref_value()` / `_voice_value()` 对不在列表中的自由输入原样下发，
   同时仍拦截带 `  ·  ` 装饰的历史脏值（避免把「云健 · 普通话 · 男声」
   写进 `tts.ref_file`）。

5. **新增 `scripts/register_voice.py`**：把参考音频注册成云端音色。
   校验时长（建议 10–30s）、自动转 24kHz 单声道 PCM16、base64 上传、
   轮询训练状态、输出可直接填进设置的 `speaker_id`。

## 不做

- 不引入付费之外的依赖，不改变 `BaseTTS` 的合成接口。
- 不改本地 XTTS 链路 —— 它仍然可用，只是慢，作为离线兜底保留。
- 不自动替用户注册账号、不开通付费服务。

## 验收方式

需要在真实凭证下走通：`register_voice.py` 训练成功 → 得到 `S_xxx`
→ 引擎选 `doubao`、参考音色填该 ID → 合成出声，且首包延迟与在线音色同级。

无凭证时只能验证到「参数构造正确、不抛 TypeError、界面可选择并保留手填值」。
