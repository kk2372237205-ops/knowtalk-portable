# 提问模式：按页码提问 + 判分后继续讲授

## 问题

现场反馈两个问题：

1. **没有到指定页码就开始提问**。问答对上明确填了页码，但一开课就把题目念了出来，
   幻灯片还没讲到那一页。
2. **作答并判分完毕后没有继续接下来的课程演讲**。评完分课堂就结束了，后面的内容不再讲。

## 根因

### 讲稿没到服务端，页码被整体忽略

现场日志（`knowtalk.log`）：

```
[提问] 会话 8c45efd8-... 启动提问式讲课: 0 段, 1 个提问点, 超时 120s
[提问] 会话 8c45efd8-... 在提问点 0 抛出题目 inline-1
[TTS队列] 开始处理段: slide_id=3, text=python是什么？
```

`0 段` 说明请求里没有可用讲稿。而 `utils/quiz_plan.py::assign_inline_questions`
在没有教学段时走的是：

```python
if not segments:
    points = list(range(len(items)))
    return points, {index: item["id"] for index, item in enumerate(items)}
```

**问答对的 `slide_id` 被直接丢掉了**，所有题目按"给出顺序"立刻问。
于是第 3 页的题在开课第一秒就被念出来，同时把幻灯片硬切到第 3 页。

讲稿为什么会空：展示页「连接后播放预设」是把**整篇讲稿一次性**投给 `/human`
（`sendPresentationFrom(0)`），服务端只把它排进 TTS 队列；而启动提问模式时
`QuizRegistry.start()` 会先 `flush_talk()` 清空该队列。两边没有任何交接，
讲稿就此蒸发，编排器只剩空分段。控制台侧若「预设文本」为空也只填了问答对，
同样得到空讲稿。

### 判分后停止讲授，是同一个原因的下游

`_advance()` 在 `asks` 之后没有可投喂的教学段，`_cursor` 越界即 `_finish()`，
课堂当场结束（只有 1 道题时尤其明显：提问 → 作答 → 评分 → 结束）。
即使讲稿存在，`Stage.FEEDBACK` 期间展示页若把自身演讲状态清掉，
判分反馈念完后也没有任何一方接着讲。

## 方案

1. **页码成为真正的触发条件**：编排器新增 `waiting_slide` 阶段，提问点带了目标页码时，
   必须等当前幻灯片到达该页才抛题；**不设任何等待时限**，等不到就一直等。
   等待期间**照常播放**（不切音频、不改按钮）——翻页发生在段落音频首帧上，停了音频就永远等不到；
   定期打日志，便于区分「在等翻页」与「卡死」。
   纯提问模式（无讲稿）下问答对按页码升序提问，不再按填写顺序。
2. **讲稿在服务端留底**：`/human` 收到含 `[PPT:N]` 的 echo 文本时记为该会话最近的讲稿；
   `/api/quiz/lecture` 未带 `text` 时回退使用它，避免"flush 一下就没了"。
3. **判分后必须继续**：有剩余教学段时，反馈念完立刻推进下一段；
   编排器不负责讲授时（无讲稿），展示页不得销毁自身演讲状态，让剩余课程继续播。

## 影响

- 填了页码的题目一定在对应页出现；PPT 没翻到就停在那页等，绝不提前念题。
- 讲稿不再因 `flush_talk()` 丢失，答完继续讲后面几页，课堂完整走完再评分。
- 不改变 `/api/quiz/lecture` 的请求/响应必填字段，仅新增可选返回项与阶段值 `waiting_slide`。
