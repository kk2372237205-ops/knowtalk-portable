# Design

## 方向

沿用设计稿（`docs/design/index.html`）定下的 **quiet-instrument**：一栏到底、靠比例与留白说话、全页五种字号两种字体、没有一条装饰性细线。

选它的理由不是风格偏好，而是它只有在这个产品身上才成立：产品唯一的核心材料是**讲稿**，而讲稿在编辑器里本来就是一栏窄文本。整页按一栏排，读页面就像读讲稿。

## 为什么要换成独立样式表

`web/index.html` 里有两千余行控制台脚本和 Bootstrap 类名。把首页样式塞进 `<style>` 会与 Bootstrap 的 `*`、`h1..h6`、`a`、`img` 规则互相踩。做法是把首页皮肤单独放进 `web/home.css`，并用 `body.home` 作为作用域根：

- 原始的 `:root` 变量（`--primary` 等）保持不动，控制台组件继续用它们；
- 首页新增一套自己的变量（`--bg`/`--ink`/`--accent`/`--board`/`--chalk`/`--hair`），只在 `.home` 作用域内生效；
- 只对**必须统一**的三处做覆盖：`body` 背景、`.navbar`（改为同栏静默条）、`.glass-card`（纸白底 + 细边）。

## 控制台为什么不缩到单栏

单栏 680 放得下讲稿与问答，放不下 PPT 页码标签选择器、手势标签行、四个并排下拉与三组按钮。控制台继续走 Bootstrap 的 `row/col-lg-*`，只把外框限宽到 1080px、底色接上纸色，让它在视觉上从属于同一套纸面，而不是另起一套。

这是本变更唯一一处刻意的不一致：**营销段单栏，控制台宽栏**。理由是前者用来读，后者用来操作。

## 演示面板的取舍

旧首页用一张悬浮题卡表达「提问模式」，读者只能看到一个结果，看不到机制。新版做成可拖动的：左侧页码、标题、要点、念稿都会跟着变，右侧六项控件一直摆着。拖到第 3 页会停下、静音、冻住并出题——这正是服务端真实的行为（`Stage.ASKING` 那一刻就静音并冻结幻灯片），不是示意动画。

无脚本时面板停在初始状态（第 3 页、已停下、题卡显示），因为那本来就是这一节要说的话。

## 素材

形象片段用 `lecturer.webp`（AI 生成的示意人像，非真实客户），已注明。白底人像贴在米色上会在边缘留一个白方块，用 `mix-blend-mode: multiply` 让白融进底色，比抠图省事且没有硬边。

## 未采纳的方案

- **保留深色 sticky 导航**：与单栏纸面对冲，且深色条会把首屏切成两段。
- **能力段用三列卡片**：单栏 680 摆三列，每列 200px，界面片段里的字会掉到 11px 以下。
- **加客户名单 / 案例段**：没有真实客户，编造违反内容诚实原则。
- **把控制台也改成单栏**：会牺牲可用性（标签选择器挤成一列，滚动距离翻倍）。
