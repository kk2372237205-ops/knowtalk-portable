# Tasks

## 1. 失败可见的基础设施

- [x] 1.1 在 `tts/base_tts.py` 新增 `TTSSynthesisError(message, hint='')`，作为引擎上报合成失败的统一异常类型。验证：单元测试可构造并读取 `message` 与 `hint`
- [x] 1.2 改造 `tts/edge.py`：删除第 51-53 行的静默 `return`，改为抛 `TTSSynthesisError`，`hint` 说明"该引擎依赖微软在线服务，当前不可用，建议改用离线引擎"。验证：单元测试用打桩让合成产出为空，断言抛出异常且 `hint` 含可操作建议
- [x] 1.3 让 `tts/edge.py` 的内部异常不再被吞掉：`__main` 中捕获后重新抛出（或记录后由调用点判定），确保没有产出时必然走上抛错路径。验证：单元测试断言上层收到异常而不是空返回

## 2. 离线引擎实现

- [x] 2.1 新增 `tts/sapi.py`，注册名为 `sapi` 的 TTS 引擎，用 `comtypes` 驱动 Windows SAPI 把文本合成到临时 wav。验证：在 Windows 上实际合成一段中文并确认 wav 非空
- [x] 2.2 语音选择：枚举系统已安装语音，优先选目标语言（中文）语音；没有可用语音或没有中文语音时抛 `TTSSynthesisError` 并说明。验证：单元测试分别覆盖"有中文语音""只有非中文语音""无任何语音"三种情形（后两种用打桩）
- [x] 2.3 非 Windows 平台：模块导入或首次使用时明确报错说明平台不支持，不得泄漏原始 `ImportError`。验证：单元测试打桩平台判定，断言抛出带说明的异常
- [x] 2.4 产出对齐既有约定：16 kHz 单声道、按 `self.chunk` 切帧、首帧 `status:start`、末帧 `status:end`、合并 `textevent`。验证：单元测试断言帧长、通道数、采样率与事件点与既有引擎一致
- [x] 2.5 语速映射：把既有 `--TTS_RATE`（如 `+20%`）映射到 SAPI 的 `Rate`（-10..10）并记录换算规则。验证：单元测试覆盖若干百分比到整数的映射与越界裁剪
- [x] 2.6 临时文件清理：合成用的临时 wav MUST 在成功与失败路径都被删除。验证：单元测试分别检查成功与失败后临时目录无残留

## 3. 回退编排

- [x] 3.1 新增 `--TTS_FALLBACK` 参数（含运行期设置项），默认空表示不启用回退。验证：参数出现在 `--help` 与设置接口中
- [x] 3.2 在 `BaseTTS.process_tts` 中实现至多一次的回退：主引擎抛 `TTSSynthesisError` 时，若备用引擎可用则用同一段文本与同一组参数再合成一次，并记录 WARNING 说明发生了回退。验证：单元测试打桩主引擎失败、备用引擎成功，断言备用被调用一次且产出音频
- [x] 3.3 备用引擎与主引擎同名时视为无效配置，明确报告且不重试。验证：单元测试断言该情形下只调用一次且报告了无效配置
- [x] 3.4 备用引擎同样失败时报告两次失败并终止，不再尝试任何引擎（不得成环）。验证：单元测试断言调用总次数不超过 2
- [x] 3.5 未配置备用引擎时明确报告失败与原因。验证：单元测试断言日志含主引擎的 `hint`
- [x] 3.6 失败限定在单次请求内：一次失败后新的合成请求仍能正常处理。验证：单元测试先制造一次失败再提交一次正常请求，断言后者成功
