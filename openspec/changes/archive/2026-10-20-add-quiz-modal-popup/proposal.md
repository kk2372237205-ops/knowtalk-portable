# Proposal

## Why

提问模式当前把题目卡片以内嵌形式挂在 `#quizPanelHost`（在提问配置卡片内部）渲染。这有两个体验问题：

1. **不够显眼**：讲课时数字人停下来问问题，但题目只是页面角落的一张卡片，学员容易错过"现在要答题了"的信号。
2. **作答方式没有"选择"感**：文字输入框与"语音作答"按钮同时平铺，用户不会意识到"可以二选一"。

用户明确要求：**没有提问时不打扰；一旦抛出问题，要以弹窗形式把题目写出来，并让我选择用语音还是文字作答。** 这改变了前端对外可观察的呈现行为，因此先建本变更。

## What Changes

- 把提问卡片的渲染容器 `#quizPanelHost` 从内嵌区块改为**模态浮层**：固定全屏、半透明遮罩居中卡片。题目到达（等待作答 / 判分）时浮层显示，讲授 / 念题干 / 结束后浮层自动消失——即"期间没有提问问题"时不出现任何弹窗。
- 卡片内新增**作答方式切换**（文字 / 语音）：默认文字，点击"语音"切换为录音区；两种方式的底层接口与现有行为不变（文字走 `/api/quiz/answer`，语音走 `/api/quiz/answer/audio` 转写后走同一条判分路径）。
- 仅改前端呈现与少量交互类；**不改动任何接口契约、状态机语义、判分逻辑**。后端 `quiz-mode` 能力规格已覆盖这些行为，本变更只补全"前端必须以弹窗呈现"这一可观察约束。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `quiz-mode`: 在现有能力上补充一条要求——提问在客户端 MUST 以模态弹窗呈现，且 MUST 同时提供语音与文字两种作答入口供选择。

## Impact

- **修改前端**：`web/index.html`（新增 `#quizPanelHost` 模态样式与作答方式切换样式）、`web/quiz-panel.js`（`buildCard` 增加作答方式切换；挂载时给 host 加 `quiz-modal-open` 类，卸载时移除，便于 CSS 控制显隐）。
- **新增依赖**：无。
- **不受影响**：`/api/quiz/*` 全部接口、状态机、判分、题库、语音转写；普通模式（未启用提问）行为完全不变。
- **测试**：`tests/js/quiz-panel.test.js` 现有断言（卡片挂在 host、单定时器、各阶段显隐、语音转写）MUST 仍全绿；新增弹窗显隐与作答方式切换的断言。
