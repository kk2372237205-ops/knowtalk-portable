# Spec Delta

## Purpose

定义语音合成引擎的统一契约：引擎如何选择、离线可用性如何保证、合成失败如何可见、回退如何工作、默认配置如何保证开箱即可发声，以及产出必须满足的采样率与分块约定。

## ADDED Requirements

### Requirement: 开箱即可发声的默认兜底

在提供系统离线语音能力的平台上，未显式配置备用引擎时，服务 MUST 默认启用该平台的离线引擎作为兜底。显式配置 MUST 优先于该默认值，且 MUST 能关闭兜底。

#### Scenario: 未做任何配置即启动

- **WHEN** 在提供系统离线语音能力的平台上，未通过命令行或运行期设置配置备用引擎就启动服务
- **THEN** 生效的备用引擎 MUST 是该平台的离线引擎
- **AND** 主引擎失败时 MUST 自动改用该离线引擎并产出音频

#### Scenario: 显式关闭兜底

- **WHEN** 使用者显式把备用引擎设为"不回退"
- **THEN** 服务 MUST NOT 在失败时改用其它引擎
- **AND** MUST 明确报告失败与原因

#### Scenario: 平台不提供离线语音能力

- **WHEN** 运行平台不提供系统离线语音能力
- **THEN** 生效的备用引擎 MUST NOT 指向该离线引擎
- **AND** 该平台的合成行为 MUST 与未引入本要求时一致

### Requirement: 主引擎反复失败时必须在会话内短路，且不得丢弃文本

主引擎在一个会话内被反复证实失败、且备用引擎已成功接管后，本会话后续合成 MUST 直接使用备用引擎，不再重复等待同一个失败。短路 MUST NOT 导致文本被拒绝、跳过或丢弃；新会话 MUST 重新尝试主引擎。

#### Scenario: 反复失败后短路

- **WHEN** 主引擎在同一会话内连续多次合成失败，且每次失败都已由备用引擎成功接管
- **THEN** 该会话后续的合成 MUST 直接使用备用引擎
- **AND** MUST NOT 再次调用已被证实失败的主引擎

#### Scenario: 单次失败不短路

- **WHEN** 主引擎只失败过一次，随后的合成由主引擎成功完成
- **THEN** 服务 MUST NOT 进入短路状态
- **AND** 后续合成 MUST 继续优先使用主引擎

#### Scenario: 短路状态下文本仍被合成

- **WHEN** 会话处于短路状态并提交了新的文本
- **THEN** 该文本 MUST 仍被合成并产出音频
- **AND** MUST NOT 被拒绝、跳过或丢弃

#### Scenario: 没有可接管的备用引擎

- **WHEN** 主引擎失败且没有任何可用的备用引擎
- **THEN** 服务 MUST NOT 进入短路状态
- **AND** 后续请求 MUST 继续尝试主引擎

#### Scenario: 备用引擎失效时解除短路

- **WHEN** 会话处于短路状态，而备用引擎在后续合成中失败
- **THEN** 服务 MUST 解除短路状态
- **AND** 下一次合成 MUST 重新尝试主引擎

#### Scenario: 新会话重新尝试主引擎

- **WHEN** 建立一个新的会话
- **THEN** 该会话 MUST 重新尝试主引擎，而不是沿用上一个会话的短路状态
