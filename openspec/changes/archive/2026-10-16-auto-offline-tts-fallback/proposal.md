# Proposal

## Why

**开箱状态下的课堂是无声的。** 直接启动 `app.py`、不动任何配置时：

- 默认引擎 `edgetts` 已被微软服务端持续拒绝（`WSServerHandshakeError 403`）。实测三种方式全部失败——直连（TLS 1.3 握手成功，说明是服务端拒绝而非网络不通）、走本机代理、以及脱离项目的最朴素 `edge_tts.Communicate()` 调用；本机 `edge-tts` 已是 PyPI 最新版 `7.2.8`，**没有升级路径**。
- 项目**已经有**离线引擎 `sapi`，也**已经有**回退机制（`add-offline-tts-engine`），但两者的默认值都是空：`--TTS_FALLBACK` 默认 `''`、`tts.fallback` 默认 `''`。于是默认状态恰好是"首选引擎必然失败 + 无兜底"，实测一段 12 页讲稿**12 段全部无声**。
- 更糟的是**修好它必须先知道它坏了**：使用者若不读日志，只会看到"数字人突然不说话了"。

已有的设置页入口与命令行开关都要求使用者先诊断、再配置。本次变更把"能出声"变成默认行为。

## What Changes

- **默认兜底**：在提供系统离线语音能力的平台上（Windows），未显式配置备用引擎时默认使用离线引擎 `sapi`。显式配置（设置页或 `--TTS_FALLBACK`）仍然优先；在设置页选「（不回退）」可关闭。其它平台不使用该默认值——系统语音引擎在该平台本就不可用，指向它只会制造一个必然失败的配置项。
- **会话内自适应短路**：主引擎在一个会话内被反复证实失败、且备用引擎已成功接管后，本会话后续合成直接使用备用引擎，不再为每段文本重复等待一次相同的失败。实测每段失败等待约 3–4 秒，12 页讲稿累计约 40 秒空白停顿。新会话必须重新尝试主引擎——外部服务恢复后自动回到更好的音质。
- **如实展示**：设置页展示"当前实际生效的备用引擎"及其来源（默认值同样展示），使"为什么突然变成机械音"可从界面解释，而不只藏在日志里。
- **文档**：说明开箱行为、如何关闭兜底、以及音质取舍。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `speech-synthesis`：新增两条要求——「开箱即可发声的默认兜底」与「主引擎反复失败时的会话内短路」。既有要求（失败可见性、回退至多一次、不得成环、产出采样率与分块约定、失败不得扩散到其它会话或后续请求）**全部保持原意**：短路后文本仍必须被合成并产出音频，不得被拒绝或丢弃；新会话必须重新尝试主引擎。

  注：该能力由尚未归档的 `add-offline-tts-engine` 引入，`openspec/specs/speech-synthesis/` 尚无基线，因此本变更的 delta 用 `## ADDED Requirements` 表达（归档时与前者合并到同一能力），而不是 `## MODIFIED Requirements`。

## Impact

- **修改文件**：`config.py`（`--TTS_FALLBACK` 默认值）、`utils/settings_store.py`（`tts.fallback` 默认值，与平台判定共用一个判据）、`tts/base_tts.py`（会话内短路）、`README.md`（开箱行为说明）。
- **不改动**：`tts/sapi.py`、`tts/edge.py`、回退"至多一次、不得成环"的规则、音频帧契约、任何 HTTP 接口。
- **不改动前端**：设置页读取的是后端解析后的取值，默认值变化会自动反映到下拉框的选中项，无需改 `web/settings.html`。
- **已有部署不受影响**：只持久化用户显式写入过的字段；已显式配置过备用引擎（或显式设为不回退）的部署，其取值优先级仍高于新默认值。
- **平台差异**：默认兜底仅 Windows 生效；其它平台行为与变更前完全一致。
- **已知取舍**：兜底生效时音质为 SAPI 拼接音，明显不如神经音色。这是"可用优先"的取舍；外部服务恢复后新会话会自动回到 `edgetts`。
- **不会更差**：若 `sapi` 因缺少 `comtypes` 或系统无中文语音而不可用，行为退化为变更前（明确报错、不发声）。
