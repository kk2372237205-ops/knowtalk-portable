# 端侧菜单对齐课程知识库

## 为什么

端侧那排按钮原本是通用展项话术：课程介绍 / 实训安排 / 报名方式 / 公司介绍。
但知识库里只有一门课——`python-base`《Python教程（基础）》（254 页 / 271 个片段），
教材里没有「实训安排」「报名方式」这类段落，点下去只能得到「课程资料中未涉及该内容」。

换提示词也救不回来，因为在换之前还有两个更前置的问题：

1. **`/rag/ask` 的 `course_id` 默认值是个已不存在的课程**
   （`rail-passenger-traffic`）。端侧按钮、语音提问都不传 `course_id`，于是检索
   落到一个空课程上，`course_has_data()` 直接返回 False，`vector_candidates: 0`，
   哪怕提示词写得再准也一律是「课程资料中未涉及该内容」。实测不带 `course_id`
   请求，`retrieval.latency_ms` 只有 0.01——根本没检索。

2. **问法决定成败**。同一主题换种问法，命中页从 `p7` 飘到 `p55`；
   一次问两个主题，模型会把两个答案拼在一起，还时而带出 `while True:` 这类代码块，
   数字人没法念。菜单是固定按钮，答不稳等于每次展项表现都不一样。

## 做什么

1. **RAG 侧兜底选课**：`course_id` 缺省时，若当前恰好有一门「已启用且已索引」
   的课程就直接用它；多门课并存时不猜（猜错课程比报没命中更误导人）。
   同时把 `AskRequest.course_id` 的默认值从硬编码旧课程改为 `None`。
2. **菜单换成课程主线 5 条**，每条提示词都在真实 RAG 链路（向量 + BM25 + 重排 + 生成）
   上验证过命中页与答案：
   - 课程导览 / 语法基础 / 流程控制 / 函数与类 / 实战项目
3. **按钮间距随数量收紧**：5 个起把间隔从 10 降到 6，避免顶出舞台宽度被裁掉。

## 影响

- `data/kiosk/menus.json`（本地数据，不入库）：4 条旧菜单替换为 5 条。
- `utils/kiosk_store.py` 的 `_default_menus()`：首次运行的示例菜单同步为同一套。
- `rag_service/api.py`、`rag_service/schemas.py`：问答缺省选课。
- `desktop_app.py` 的 `_rebuild_menu_bar()`：按钮间距。
- 不改任何前端字段、不改菜单的增删改接口。
