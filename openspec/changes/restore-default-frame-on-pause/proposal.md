# 暂停播放时画面回落默认帧

## 问题

展示页的「暂停播放」目前是**纯前端**动作（`web/knowtalk-chat.html::togglePlayback`）：

```js
if (remoteAudioTrack) remoteAudioTrack.enabled = false;
audio.pause();
playbackPaused = true;
```

只关掉远端音频轨、暂停 `<audio>` 元素，**服务端完全不知情**。于是：

- 视频轨照旧以 20fps 推流，推理线程不停；
- 但浏览器那边音频已经断了，画面还在动——或者（更常见的现象）画面停在**最后一个推理帧**上，
  而最后一个推理帧往往是**张着嘴**的。

用户看到的就是「人僵在那里、嘴还张着」，既不像暂停，也不像正常状态。

另外，上一轮把「推理缺帧时的补帧」从「原始闭嘴帧」改成了「沿用上一张已输出画面」，
这在说话途中是对的（避免嘴在开合之间跳），但**暂停时反而更明显**——因为没有新的推理帧了，
`_last_out_frame` 就一直被重复，嘴定格在张开姿势。

## 方案

给会话加一个**播放暂停态**，由前端显式通知服务端：

1. 新增接口 `POST /api/playback`，请求体 `{sessionid, paused}`，切换该会话的暂停态。
2. 暂停期间，输出画面 MUST 用**该形象的基础素材帧**（闭嘴、静止），不再输出推理帧；
   音频侧维持现有行为（前端已经把音频轨关掉了），不引入新的时间线语义。
3. 恢复播放时清除暂停态，下一帧即恢复推理画面。
   **不 flush 队列、不重播**——继续播放的语义是「接着看」，不是「从头来」。
4. 前端在 `togglePlayback()` 的暂停/恢复两支里各调一次该接口；
   调不通只记警告，不阻断本地静音（网络抖动不该让暂停按钮失灵）。

## 影响

- 暂停时画面回到默认姿态（闭嘴静止），与「暂停」这一操作一致。
- 恢复后立刻继续，不重播、不跳段。
- 只覆盖展示页的「暂停播放」按钮；提问模式与演讲暂停各有自己的链路，本次不动。
- 若前端调接口失败（服务重启、网络问题），退化为现状（画面定格），不会更糟。
