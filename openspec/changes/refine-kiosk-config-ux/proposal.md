# 桌面端配置动线收敛：开播置顶、背景独立成页、迎宾可触发动作

## 为什么

上一轮把导航按「演讲 / 展览」重排了，但真机上用一遍还是有几个具体问题：

1. **「人脸接近检测」的参数区控件是坏的**：摄像头与检测方式用系统原生 `ttk.Combobox`、
   灵敏度用 1990 年代的 `tk.Scale`（值显示在滑块上方，把整行顶歪），
   而同一页其它控件已经是自绘开关 / 圆角下拉，混在深色卡片上像贴上去的。
   更严重的是**总开关不会启停进程**——拨了开关必须再点「保存感应参数」才落盘，
   点了保存又会把「启用」一起写进去，用户根本不知道现在到底有没有在检测。
2. **音频配置分散**：参考音色在「开播」和「形象与设置」各有一份，两处都能改，
   改完哪份生效说不清。音频是**上课前一次性配好**的东西，不该混在开播动线里。
3. **「画面背景」藏在开播页左栏底部**：它是舱体外观的一部分，和「换哪个形象」一样属于
   展项配置，却要开播时才想得起来。
4. **「开播」不是第一个**：两个模式下都要在导航里先找「启动 / 上课」分组才能点，
   而它其实是每天第一个动作。
5. **闲时只有视频**：`idle.json` 里的 `video` 从头到尾没有任何消费方（主服务不读、
   桌面端不播），配了等于没配。现场真正想要的是「没人时数字人自己轻轻动起来」。
6. **迎宾只有一句话**：检测到有人只会念迎宾语，站到舱前第一眼看到的是静止画面。

## 做什么

1. **接近检测参数区重做**：摄像头 / 检测方式改圆角下拉与分段器，
   灵敏度改自绘滑块（轨道 + 游标 + 数值与「低/中/高」定性词），无人判定沿用主题输入框。
   总开关**直接启停检测进程**（开=落盘 enabled 并拉起 `scripts/proximity_detect.py`，
   关=落盘并杀 pid），保留「保存感应参数」只写参数不动开关。
2. **参考音色只留在「形象与设置 → 语音与音频」**：开播页删掉音色卡片墙，
   改为一行「当前音色 + 去设置音色」，开播不再下发 `tts.ref_file`（沿用设置里的值）。
3. **新增「背景设置」页**：从开播页左栏搬出来，独立成页——
   形象选择 + 纯色色板 + 已上传图片卡片 + 上传按钮 + 实时预览图。
4. **导航置顶**：演讲模式下「开播」在「上课」分组第一位，展览模式下在「启动」分组第一位；
   「背景设置」进「全息舱」分组（演讲模式放在「上课」分组，开播之后）。
5. **闲时动作**：`idle.action = {avatar, gesture}` 取代 `idle.video`；
   有人离开（`present` true→false）时由主服务请求该动作并**循环播放**。
6. **迎宾动作**：`proximity.trigger_action = {avatar, gesture}`；
   有人走近（`present` false→true）时先请求该动作（播放一遍），再念迎宾语。

## 影响

- `utils/kiosk_store.py`：`_default_idle()` 增 `action`，`_default_proximity()` 增 `trigger_action`；
  `set_idle` / `set_proximity` 的白名单同步（`video` 保留为历史字段，不再由界面写入）。
- `server/kiosk_routes.py`：新增 `_play_gesture()`；`proximity_event` 在状态翻转时请求动作，
  返回体的 `action` 增加 `gesture` 取值。
- `avatars/base_avatar.py`：`request_gesture(name, repeat=False)`，循环动作播满一遍不清回默认素材。
- `desktop_app.py`：新增 `ThemedSlider` / `ActionPicker` / `BackgroundPage`；
  `IdlePage` 的闲时卡片与感应卡片重做；`AvatarPage` 去掉音色与背景两块；
  `MainPage.MODE_NAV` 重排并接入 `bg` 页。
- 不改任何已有接口路径；`/api/kiosk/idle` 与 `/api/kiosk/proximity` 只**新增**字段。
- 动作按形象分目录存放，故动作配置必须带 `avatar`：若配置的形象与当前会话形象不一致，
  主服务 MUST 跳过播放并在日志里说明原因（帧尺寸与人脸框对不上，硬播会糊）。
