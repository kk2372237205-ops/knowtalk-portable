# Proposal

## Why

现在这套数字人只能"一路讲到底"：`POST /human` 把讲稿按 `[PPT:N]` 分段后逐段送进 TTS，中间没有任何与学员交互的机会。课堂实际上最需要的是**停下来问一句、等学生答、再继续讲**——而这件事目前完全做不到。

提问模式要解决的正是这个缺口：在讲课过程中的若干位置让数字人停住、PPT 也随之停住，抛出一个问题，学员用文字或语音作答，AI 判断对错并给出反馈，然后继续讲课。原有的"一路讲下去"保持为**普通模式**，行为不变。

## What Changes

- **新增提问模式**，作为独立的一层编排，**不修改既有 `/human` 的契约**（"受理后立即返回、不等待朗读完成"以及"该段音频开始播放时才切页"都保持不变）。停放下一段的发送即可让讲课与切页同时停住，无需在朗读流程内部插入阻塞。
- 一次"提问式讲课"由服务端状态机编排：`教学段 → 提问点 → 追问等待 → 判分 → 反馈播报 → 下一教学段`。每个会话独立维护自己的进度。
- **提问点可配置、可随机**：由调用方在发起时给出候选范围与数量，支持三种选取方式（随机抽取 N 处 / 按固定间隔 / 手动指定位置），并支持限定在指定的幻灯片范围内抽取。随机抽取 MUST 可复现（同一次配置与同一随机种子给出相同的提问点）。
- **可按幻灯片精确指定题目**：发起时可给出一张「幻灯片编号 → 题目标识」的绑定表，被绑定的提问点 MUST 问指定的那道题，不被随机或固定间隔选取覆盖；未被绑定的提问点才从未被占用的题目中按选取方式取。绑定引用不存在的题目、绑定到不属于候选提问点的幻灯片、或同一题被绑到多个幻灯片时，发起请求 MUST 被拒绝并指明冲突项。
- **题库与出题**：教师可预先录入题目；也可让 LLM 依据当前幻灯片内容与知识库（RAG）生成题目后落库。题目支持参考答案与评判要点，供判分使用。
- **发起时可直接给出问答对（内联问答对）**：教师可以在发起请求里一并给出若干「题目 + 参考答案（+ 评判要点）」，这些问答对**不依赖题库落库、也不依赖幻灯片文字或自动出题**，本次讲课直接用它们提问。题库为空时同样可以发起。给出内联问答对时，**提问数量由问答对数量决定**，不再从题库抽取、也不受请求中数量字段影响。
- **内联问答对可指定提问所在幻灯片，也可不指定讲稿**：每条问答对 MAY 指定要问在第几页（该页不是候选提问点、或两对指定同一页时必须以业务错误拒绝并指明冲突项）；未指定的按问答对给出的顺序依次分配给提问点。**讲稿 MAY 省略**——省略时退化为「纯提问」：只按顺序逐题提问，不朗读任何教学段，判分反馈朗读完最后一题即结束。内联问答对与「幻灯片 → 题目标识」绑定表不得同时使用。
- **判分与反馈**：用对话 LLM 依据参考答案与评判要点判定学员回答是否覆盖要点，产出结论与反馈语；反馈由数字人朗读后继续讲课。LLM 不可用时 MUST 降级为"只记录不判定"并明确告知，不得卡住课堂。
- **作答方式**：文字直接提交；语音通过新增的语音转写接口转成文字后走同一条判分路径。
- **新增语音转写能力**：以 `faster-whisper` 在本地做中文识别（本机仅有 CPU，故 MUST 支持模型规格选择与延迟说明），模型可放本地目录；**新增依赖** `faster-whisper`。
- **课堂面接口不受访问口令拦截**：学员提问与作答发生在课堂进行中，MUST NOT 要求口令；而题库增删改与 AI 出题属于教师配置面，MUST 受口令约束。这与 `rag-sidecar-control`、`session-control` 已有的分界方式一致。
- 普通模式 MUST 完全不受影响：未启用提问模式的会话，其接口行为、切页时机与朗读时序 MUST 与本次变更前一致。

## Capabilities

### New Capabilities

- `quiz-mode`: 提问式讲课的编排——提问点的选取与随机语义、题库与 AI 出题、提问与作答流程、进度与状态查询、LLM 判分与反馈、模式并存与降级行为，以及课堂面接口的口令豁免边界。
- `speech-to-text`: 语音转写接口——音频受理与格式约束、中文识别、模型选择与本地模型目录、CPU 下的延迟与超时行为、识别失败的处理，以及接口的口令与体积约束。

### Modified Capabilities

无。

逐个核对过：`digital-human-api` 的「文本驱动的 echo 模式」「echo 模式按段切页朗读」「幻灯片标签解析与清洗」与 `slide-material-management` 的「标签驱动的幻灯片切换时机」都**不需要改**——提问模式不在 `/human` 内部阻塞，也不引入新标签，而是另起一层编排，因此这些要求的文本与场景仍然成立。提问点配置是**发起时传入的参数**（不是全局设置），所以 `runtime-configuration` 的设置目录也不受影响；按 `llm-configuration`、`rag-sidecar-control` 的既有先例，各自的口令边界由各自能力声明。

## Impact

- **新增后端**：提问编排状态机、题库存储、语音转写封装、以及 `/api/quiz/*` 与语音转写接口。
- **新增依赖**：`faster-whisper`（本地推理，CPU 可跑）。MUST 首次使用时下载模型或使用本地模型目录；本机无 GPU，中文识别建议使用 `small` 级别模型，延迟需在文档中如实说明。
- **新增数据**：题库与问答记录放在 `data/` 下（已被忽略规则排除），并 MUST 有明确的文件格式与损坏回退行为。
- **修改前端**：`web/index.html` 增加提问卡片（题目、作答输入、语音作答按钮、判分结果与反馈）与提问模式开关；普通模式下这些控件不出现、不干扰既有流程。提问模式卡片另增**问答对编辑区**（增删「题目 / 参考答案 / 可选页码」行），填了问答对即以请求体 `questions` 直接发起，**不落库、也不要求先有讲稿**。
- **不受影响**：`/human`、`/humanaudio`、`/interrupt_talk`、`/is_speaking`、`/llm_status`、`/api/slides*`、`/api/current_slide` 的既有行为与返回结构。
- **运行环境**：语音识别与判分都会调用本地推理或外部 LLM，课堂网络中断时 MUST 有可预期的降级路径。
