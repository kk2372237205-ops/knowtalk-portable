- [x] 1.1 在 conda 环境 `livetalking`（Python 3.10.21、torch 2.14.0+cpu、无 CUDA）安装 `faster-whisper`，确认与既有 `torch`/`numpy` 版本共存不冲突。验证：`python -c "import faster_whisper, torch, numpy; print(faster_whisper.__version__, torch.__version__, numpy.__version__)"` 成功输出

- [x] 1.3 实测 CPU 上转写一段 3–5 秒中文语音的耗时与识别质量，把真实数字记入文档。验证：给出「延迟区间 + 识别示例 + 推荐规格」三项实测结论，MUST NOT 用"应该可以"代替
- [x] 1.4 若 1.3 的延迟不可接受，评估退路（改用 `base` 规格 / 浏览器 Web Speech API）并在 design.md 追加决策。验证：给出结论与依据，不允许悬空
      ✅ **结论：延迟可接受（CPU int8 RTF 0.26–0.59，约 1.7–3.8 倍实时），不启用退路**，保留 `small` 为默认规格。结论已记入 design.md。
      ⚠️ **数字修正记录**：初测曾记下单一值 RTF 0.292，但那是机器较空闲时、带预热的一次测量；同机同时段复测同一段音频得到 0.32–0.59，波动主要来自 CPU 机器状态而非实现差异。**文档一律用区间 0.26–0.59，禁止再写单一好看的数字。**
      A/B 实测（同一音频、同一模型、各 5 轮中位数）确认该波动与 `initial_prompt` 无关：带提示 3.064 s vs 不带 2.983 s，开销仅 2.7%。
- [x] 1.5 处理并记录依赖覆盖陷阱：安装 `faster-whisper` 会引入 CPU 版 `onnxruntime`，覆盖既有的 `onnxruntime-gpu` 使其丢失 CUDA provider。验证：`onnxruntime.get_available_providers()` 中 `CUDAExecutionProvider` 存在；且该修复步骤写入文档，避免别人重装依赖后再次静默丢失
- [x] 1.6 确认简体输出为必需项：默认 `language="zh"` 会输出**繁体**，必须传简体 `initial_prompt`（或等效手段）。验证：单元测试断言繁体字形不出现
