# 画布工作流

## Why

现在开播要在一个表单里分别挑形象、声音、课件、讲稿，四者之间的关系只存在于用户脑子里：
「这套课用这个形象、配这套 PPT、接这门知识库、加这两个动作」这件事没法存下来，也传不出去。
换一门课就得把下拉重新拨一遍，录播现场很容易拨错。

用户要求加一个画布：**数字人可以通过连线连接 PPT、知识库、动作**。定位是**配置编排**——
先在画布上把一次开播要用到的东西连成一张图存下来，开播时按图把参数灌进工作台，
不做运行时执行引擎。

## What Changes

- 新增「流程」这一级对象：一张图 = 若干节点 + 若干连线，存成 `data/workflows/{id}.json`。
- 四类节点：
  - **数字人**（根节点）：形象 ID、参考音色、参考文本；
  - **PPT**：课件 ID；
  - **知识库**：课程 ID 与课程名；
  - **动作**：绑定到某个形象下的手势 ID 与显示名。
- 新增画布页 `/workflow.html`：左侧节点库、中间画布、右侧属性面板；
  节点可拖动摆位，从节点右侧圆点拖到另一个节点即连一条线，可删点删线。
- 连线规则由后端在保存时统一裁决：一张图只允许一个数字人节点；
  非数字人节点必须且只能挂在数字人上；禁止自环与重复边。
- **自动保存**：任何改动在停顿后落盘，不需要用户点保存；并发写用原子替换。
- 新增开播入口约定：`/workbench.html?workflow=<id>` 打开时按图把形象、音色、课件灌进表单，
  左栏显示当前流程名；图里引用的资源已被删除时，工作台 MUST 提示而不是静默用空值。
- 工作台左栏新增「流程」入口，画布页沿用 `.site-bar` 与纸面设计令牌。

## Impact

- 新增：`utils/workflow_store.py`（读写与校验）、`server/workflow_routes.py`（CRUD + plan）、
  `web/workflow.html`、`web/workflow.css`、`web/workflow.js`、`tests/test_workflow_canvas.py`。
- 修改：`app.py`（注册路由，需在 `add_static('/')` 之前）、`web/workbench.html`
  （左栏入口、`?workflow=` 加载、当前流程显示）、`web/workbench.css`、
  可能需要 `web/shell.css`（顶栏「流程」选中态）。
- 数据：新增目录 `data/workflows/`，`/data/` 已在 gitignore 内，不入库。
- 不引入第三方依赖，画布用原生 DOM + SVG 连线，不引图形库。
- 不做：分支条件、循环、多数字人同图、带时间轴的编排、流程模板市场（各自另立变更）。
- 不做：把流程图编译成讲稿脚本；讲稿预设仍存在浏览器 localStorage，流程不引用它。
