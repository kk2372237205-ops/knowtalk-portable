# Spec Delta

## Purpose

让数字人在讲课时按讲稿的指示做出手势：一张形象的素材之外，可以在 `data/avatars/{avatar_id}/gestures/` 下登记多套动作素材；讲稿里用标签在指定位置触发某个手势，渲染层从该处换成手势的帧序列、只完整播一遍、然后自动回到默认姿态。手势是"说话同时做动作"，不是"停下来说话前做动作"，因此必须与语音时间线并行，并且不能阻塞或打断朗读。

## ADDED Requirements

### Requirement: 手势素材按形象登记且可被发现

一套手势素材 MUST 存放在 `data/avatars/{avatar_id}/gestures/{gesture_id}/` 下，且 MUST 包含与默认素材同构的三件套：`full_imgs/`（全帧序列）、`face_imgs/`（逐帧对齐的人脸裁剪）、`coords.pkl`（逐帧人脸框）。`gesture_id` MUST 只包含 `A-Za-z0-9`、下划线、点与连字符。

三件套任一项缺失或无有效图片时，该手势 MUST 被视为不可用，MUST NOT 出现在可用手势列表中。

手势目录下可选存在 `gesture.json`，其 `label` 字段 MUST 作为该手势的显示名；文件缺失或 `label` 为空时，显示名 MUST 回退为该手势的 `gesture_id`。

手势素材的单帧尺寸 MUST 与默认素材一致。不一致时服务 MUST 在加载阶段将其归一化到默认素材的尺寸（含人脸框坐标按同比例缩放），并在使用前完成；MUST NOT 在会话运行过程中改变输出画面的尺寸。

形象没有任何手势目录时，查询可用手势 MUST 返回空集合，MUST NOT 视为错误。

#### Scenario: 发现可用手势

- **WHEN** 某形象的 `gestures/` 下存在三件套齐备的手势目录
- **THEN** 该手势 MUST 出现在该形象的可用手势列表中
- **AND** 列表项 MUST 含手势标识与显示名

#### Scenario: 三件套不齐

- **WHEN** 某手势目录缺少 `coords.pkl` 或 `face_imgs/` 为空
- **THEN** 该手势 MUST NOT 出现在可用手势列表中
- **AND** 同一形象下其它齐备的手势 MUST 仍正常出现

#### Scenario: 形象没有手势

- **WHEN** 查询一个没有 `gestures/` 目录的形象
- **THEN** 返回空的可用手势列表
- **AND** MUST NOT 返回业务错误

#### Scenario: 自定义显示名

- **WHEN** 手势目录下的 `gesture.json` 声明了 `label`
- **THEN** 该手势的显示名 MUST 为该 `label` 值

#### Scenario: 素材尺寸与默认素材不一致

- **WHEN** 某个手势素材的单帧尺寸与默认素材不同
- **THEN** 加载后该手势的画面尺寸 MUST 与默认素材一致
- **AND** 输出画面的尺寸 MUST NOT 在切换前后发生变化
- **AND** MUST 记录一条警告说明发生了归一化

### Requirement: 讲稿手势标签的语法与分段

`/human` 的文本中形如 `[GESTURE:<id>]` 的标签 MUST 被识别（标签名大小写不敏感），并与 `[PPT:N]` / `[slide:N]` 在同一层解析：标签 MUST 作为段落边界，段内文本 MUST NOT 再包含任何标签。

每段 MUST 携带该段应触发的手势标识；一个段落 MUST 至多携带一个手势。段内出现多个手势标签时 MUST 取第一个，其余 MUST 一并从朗读文本中移除。

段落 MUST NOT 继承上一段的手势：未带手势标签的段落，其手势 MUST 为空。

#### Scenario: 标签触发分段

- **WHEN** 提交 `"[GESTURE:explain] 我们来分析这个问题。[PPT:3] 先看第三页。"`
- **THEN** MUST 得到两段，第一段携带手势 `explain`、幻灯片为空，第二段手势为空、幻灯片为 3
- **AND** 两段朗读文本中 MUST NOT 含任何标签

#### Scenario: 标签名大小写不敏感

- **WHEN** 提交 `"[gesture:explain] 内容"`
- **THEN** MUST 与 `[GESTURE:explain]` 产生相同的分段结果

#### Scenario: 手势不跨段继承

- **WHEN** 提交 `"[GESTURE:explain] 第一段。第二段没有标签。"`（无其它标签）
- **THEN** MUST 只得到一段，该段携带手势 `explain`
- **AND** 后续未带标签的段落 MUST NOT 触发该手势

### Requirement: 手势在段首触发且只完整播放一遍

某段带手势标识时，该段音频开始播放的时刻 MUST 切换到该手势的帧序列，并 MUST 从手势的第 0 帧开始播放。该手势 MUST 只完整播放一遍，播完后 MUST 自动恢复到该形象的默认素材，并继续默认素材的循环播放。

手势 MUST NOT 改变语音时间线：切换、播放与恢复 MUST NOT 插入静音、截断或延迟该段朗读，MUST NOT 改变段落之间的顺序与切页时机。

该段音频短于手势时长时，手势 MUST 继续播放至完整一遍结束，MUST NOT 因段落结束而被截断。

#### Scenario: 段首切换并从首帧开始

- **WHEN** 一段带手势的文本开始朗读
- **THEN** 画面 MUST 切到该手势素材
- **AND** MUST 从该手势第 0 帧开始

#### Scenario: 播完一遍自动回默认

- **WHEN** 手势已连续播放满一遍的帧数且该段仍在朗读
- **THEN** 画面 MUST 回到默认素材并继续循环
- **AND** 朗读 MUST 不受影响、MUST NOT 重新开始该段

#### Scenario: 段落短于手势

- **WHEN** 带手势的段落朗读时长不足手势时长
- **THEN** 手势 MUST 仍完整播放一遍后再回默认素材

#### Scenario: 不带手势的段落行为不变

- **WHEN** 讲稿中没有任何手势标签
- **THEN** 画面 MUST 全程使用默认素材，帧序与时序 MUST 与引入手势前一致

### Requirement: 手势按素材原始时长播放

动作素材由外部视频导入，带自己的原始帧率；渲染端是「每输出一帧前进一帧」。服务 MUST 在
加载手势素材时按**当前输出帧率**重采样，使播放时长等于素材本身的时长，MUST NOT 随输出帧率
改变动作速度。

重采样 MUST 对同一套手势的全部逐帧素材（画面帧、人脸裁剪、人脸框）以及模型专属资产
使用**同一套取帧下标**，MUST NOT 只处理其中一部分。模型专属的人脸资产若恒为一份
（MuseTalk 下取自形象自身，长度 1），重采样 MUST 保持其不变而 MUST NOT 复制成多份。

素材原始帧率 MUST 由 `gesture.json` 的 `fps` 字段声明；缺失或非法时 MUST 回退到默认值
（24fps，与外部出片端一致），MUST NOT 因此让该手势不可用。

#### Scenario: 素材帧率与输出帧率不同

- **WHEN** 某手势素材为 24fps、共 107 帧（约 4.5 秒），输出帧率为 20fps
- **THEN** 加载后该手势的帧序列 MUST 为 89 帧
- **AND** 画面帧、人脸裁剪、人脸框与模型专属资产的长度 MUST 一致且逐帧对应
- **AND** 首帧 MUST 仍是素材第 0 帧、末帧 MUST 仍是素材最后一帧
- **AND** 以 20fps 播放的时长 MUST 约等于素材时长（约 4.5 秒）

#### Scenario: 帧率一致时不重采样

- **WHEN** 素材帧率与输出帧率相同
- **THEN** 加载后的帧数 MUST 与素材帧数一致，逐帧不增不减

#### Scenario: 素材未声明帧率

- **WHEN** `gesture.json` 没有 `fps` 字段，或该值无法解析为大于 0 的数
- **THEN** MUST 按默认帧率 24fps 计算重采样
- **AND** 该手势 MUST 仍可正常播放，MUST NOT 因此被摘除或降级

### Requirement: 手势播放期间嘴型仍由语音实时驱动

手势播放期间若处于说话状态，MUST 以手势素材的对应帧为底图、由口型模型按当前音频实时重绘嘴部后贴回；MUST NOT 整帧直接输出未做口型处理的素材帧。静音期间 MUST 直接输出手势素材的对应帧。

#### Scenario: 说话时贴回手势帧

- **WHEN** 手势播放期间该会话处于说话状态
- **THEN** 输出帧 MUST 以手势素材帧为底图，且嘴部区域 MUST 由当前音频驱动生成

#### Scenario: 静音时直接输出手势帧

- **WHEN** 手势播放期间该会话处于静音状态
- **THEN** 输出帧 MUST 为手势素材的对应帧

### Requirement: 切换过程不阻塞渲染且索引安全

手势素材的加载 MUST 在渲染线程之外完成；加载期间 MUST 继续输出当前素材的画面，MUST NOT 出现黑帧、长时间静止或掉帧。

帧源切换后，所有按索引取帧的操作 MUST 以当前帧源的实际长度取模，MUST NOT 因两套素材帧数不同而索引越界或抛出未捕获异常。

这条约束 MUST 同时覆盖**贴回步骤**（把推理出的人脸合成回整帧）所用的原帧、人脸框、遮罩与遮罩框，MUST NOT 只在"取整帧"这一条路径上取模、却在贴回路径上直连裸下标。

同一会话连续触发同一手势时 MUST 复用已加载的素材，MUST NOT 重复读取磁盘。

#### Scenario: 加载期间画面连续

- **WHEN** 一次切换需要读取尚未加载的手势素材
- **THEN** 加载完成前 MUST 持续输出切换前的素材画面
- **AND** MUST NOT 输出空帧或异常帧

#### Scenario: 帧数不同的两套素材

- **WHEN** 从 150 帧的默认素材切到另一帧数的手势素材并再次切回
- **THEN** 取帧 MUST 始终落在当前素材的合法范围内
- **AND** MUST NOT 抛出索引越界异常

#### Scenario: 重复触发同一手势

- **WHEN** 同一会话内两次触发同一手势
- **THEN** 第二次 MUST 复用已加载素材，MUST NOT 再次读取磁盘

### Requirement: 动作收尾交接不得丢帧或跳帧

手势播完切回默认素材的瞬间是本功能最脆弱的一段：两套素材帧数差得很多（实测默认形象
只有 1 帧、动作素材 89 帧），队列里还有一批带着旧索引的在途帧，而"已播多少帧"的进度
又是决定何时切源的唯一依据。

因此：这些在途帧 MUST 按当前帧源合法输出，贴回步骤 MUST NOT 因索引越界而失败，
失败时 MUST 退化为输出当前帧源的合法画面，MUST NOT 跳过本帧——丢帧会同时断掉该帧音频，
接收端随即欠载，观感比"贴回质量下降"严重得多。

手势进度 MUST 由渲染线程按**实际输出的视频帧**推进，MUST NOT 由推理线程按批量产出计数：
推理产出的帧要经队列才上屏，按批量计数必然超前于画面，切换时机会早于最后几帧动作真正播出。

切换后补位帧 MUST 按**新帧源**取帧，MUST NOT 继续沿用上一帧画面——上一帧属于另一套素材，
沿用它会把旧姿态钉在屏幕上直到下一帧推理到达。

#### Scenario: 动作收尾切回默认素材

- **WHEN** 手势播放到最后一帧并自动切回帧数更少的默认素材（例如默认素材只有 1 帧）
- **THEN** 切换后到达的、仍带着手势索引的在途帧 MUST 按默认素材合法输出
- **AND** 贴回步骤 MUST NOT 因索引越界而失败
- **AND** 这些帧的视频与音频 MUST 照常输出，MUST NOT 出现欠载告警

#### Scenario: 切换时机与画面一致

- **WHEN** 一套 N 帧的手势播放完毕
- **THEN** 它 MUST 恰好输出 N 个视频帧后切回默认素材
- **AND** 第 N 个输出帧 MUST 是手势素材的末帧（收尾动作不得丢失）
- **AND** MUST NOT 因推理产出超前而提前切回

#### Scenario: 切源后的补位不沿用旧素材姿态

- **WHEN** 帧源切换后立刻发生补位（推理尚未产出下一帧）
- **THEN** 补位帧 MUST 取自当前帧源
- **AND** 人眼可见的姿态 MUST NOT 停在上一个动作的某一帧上

### Requirement: 讲课过程中不得因加载动作素材而卡顿

受理一篇讲稿时，系统 MUST 在开始朗读前把该讲稿引用到的**全部**手势预加载进缓存，
MUST NOT 只预加载其中前几套；预加载 MUST 在渲染线程之外进行，MUST NOT 抢先激活任何手势
（首次画面切换仍只由段首触发）。

预加载 MUST 串行进行，MUST NOT 多套并发解码（并发会与推理抢 CPU，反而把帧率压下去）。

单套手势素材在缓存中的常驻内存 MUST 与"全帧解码后常驻"相比显著更小（全帧按需解码、只保留
最近几帧），使一篇讲稿常见数量的动作能同时留在缓存中；讲到这里时 MUST NOT 因重新读盘解码
而出现可感知的停顿。

#### Scenario: 受理即预加载讲稿用到的全部手势

- **WHEN** 一篇讲稿引用了 6 种不同的手势
- **THEN** 开始朗读前缓存中 MUST 已含这 6 套
- **AND** 朗读到第 2 个及以后的动作时 MUST NOT 再去读取磁盘
- **AND** 预加载本身 MUST NOT 改变当前画面（不得出现"没说到就开始动"）

#### Scenario: 同一手势多次出现只预加载一次

- **WHEN** 讲稿里同一手势出现多次
- **THEN** 该手势 MUST 只被加载一次

#### Scenario: 预加载不阻塞渲染

- **WHEN** 预加载尚未完成时已经开始朗读
- **THEN** 画面 MUST 持续输出默认素材，MUST NOT 出现黑帧或长时间静止
- **AND** 推理帧率 MUST NOT 因预加载而明显下降

### Requirement: 推理缺帧时动作必须继续推进

渲染端按固定输出帧率出帧，而推理产出速度可能低于该帧率（本机实测约 19fps vs 20fps）。
此时进入补位（重复输出）的帧，在手势播放期间 MUST 使用**下一帧动作画面**，
MUST NOT 直接重复上一帧——否则手臂动作会周期性停顿，肉眼即"一顿一顿"。

补位帧 MUST 保留上一张已输出画面中的人脸区域（动作素材要求头部零位移），
使嘴型不因补位而闪回闭合姿态。

补位 MUST 计入手势的播放进度：播满一遍仍 MUST 回到默认素材，MUST NOT 因补位让画面先
跑过末帧再按取模弹回起始帧。

#### Scenario: 补位时手臂继续动

- **WHEN** 手势播放期间推理产出速度低于输出帧率
- **THEN** 补位帧 MUST 取自手势序列的下一帧
- **AND** 连续若干输出帧的画面 MUST NOT 完全相同

#### Scenario: 补位不引起嘴型闪跳

- **WHEN** 手势播放期间发生补位
- **THEN** 补位帧的人脸区域 MUST 与上一张已输出画面一致
- **AND** 画面其余部分 MUST 为新一帧动作画面

#### Scenario: 补位不改变"只播一遍"

- **WHEN** 手势播放期间发生若干次补位
- **THEN** 手势仍 MUST 在播满一遍后回到默认素材
- **AND** MUST NOT 出现动作末尾跳回起始帧

### Requirement: 手势不可用时的降级与资源上限

音频已入队后若手势素材变得不可用（例如文件被删除），渲染层 MUST 降级为默认素材并记录警告，MUST NOT 中断朗读、MUST NOT 让渲染线程退出。

讲稿中引用了当前形象不可用的手势时，接口 MUST NOT 因此拒绝整篇讲稿：MUST 照常受理并朗读，MUST 把引用该手势的段落按默认素材渲染（等同该段没有手势标签），MUST 记录一条指明不可用手势名与该形象可用手势列表的警告，MUST 在响应中把该警告一并返回，MUST NOT 静默降级。同一篇讲稿中其他可用手势 MUST 照常生效。

会话持有的手势素材 MUST 有数量上限，超出上限时 MUST 淘汰最久未使用的一套。会话结束 MUST 释放其持有的手势素材。

#### Scenario: 素材在播放前消失

- **WHEN** 某段带手势的音频即将播放，但该手势素材已不可读取
- **THEN** 该段 MUST 改用默认素材继续朗读
- **AND** MUST 记录一条警告
- **AND** 渲染 MUST NOT 因此停止

#### Scenario: 讲稿引用了当前形象没有的手势

- **WHEN** 讲稿引用了当前形象不可用的手势（例如形象 88 只有 frame、thanks，讲稿却写了 `[GESTURE:chop]`）
- **THEN** 该讲稿 MUST 照常受理并朗读，MUST NOT 整篇报错
- **AND** 引用该手势的段落 MUST 按默认素材渲染
- **AND** MUST 记录一条警告，给出不可用的手势名与该形象的可用手势列表
- **AND** 响应 MUST 带上该警告，MUST NOT 静默降级
- **AND** 同一讲稿中其他可用手势 MUST 照常生效

#### Scenario: 超出素材缓存上限

- **WHEN** 一个会话先后触发的手势数量超过缓存上限
- **THEN** MUST 淘汰最久未使用的手势素材
- **AND** 后续再次触发该手势时 MUST 能重新加载并正常播放

#### Scenario: 会话结束释放资源

- **WHEN** 会话被回收
- **THEN** 该会话持有的手势素材 MUST 被释放

### Requirement: 手势行为按会话隔离

手势的当前状态、已加载素材与播放进度 MUST 按会话独立保存。一个会话切换或播放手势 MUST NOT 改变其它会话的画面帧源与播放进度。

#### Scenario: 两个会话各播各的

- **WHEN** 会话 A 正在播放某手势，同时会话 B 播放另一个手势或默认素材
- **THEN** 两个会话的画面 MUST 各自使用自己的当前素材
- **AND** A 的播放进度变化 MUST NOT 影响 B

### Requirement: 归一化后的画面与人脸框必须仍可直接用于逐帧贴回

素材尺寸归一化后产生的人脸框 MUST 是可直接用于逐帧贴回的**整数像素坐标**（可直接得出贴回区域的宽高），MUST NOT 产生需要下游再转换一次的取值。提出这条要求的直接原因是一次实测缺陷：缩放产生浮点坐标后，贴回步骤在**每一帧**都失败，表现成"手势期间嘴不动"，而失败只留下一条告警，从画面上几乎无法反查。

#### Scenario: 归一化后的人脸框可直接用于贴回

- **WHEN** 某手势素材的尺寸与默认素材不一致，加载时触发了归一化
- **THEN** 归一化后的人脸框 MUST 能直接作为贴回区域的宽高来源使用，MUST NOT 需要调用方再做取整
- **AND** 贴回步骤 MUST NOT 因坐标取值类型而失败

#### Scenario: 贴回步骤自身也必须容错

- **WHEN** 传入的人脸框带有非整数取值
- **THEN** 贴回步骤 MUST 自行取整并继续，MUST NOT 逐帧抛错
- **AND** 若取整后区域尺寸小于一个像素，MUST 跳过本帧贴回并记录可定位的告警，MUST NOT 中断渲染线程
