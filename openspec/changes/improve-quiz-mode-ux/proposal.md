# Proposal

## Why

提问模式上线后暴露出三个实际使用问题：

1. **开启提问模式会听到"两段演讲"**。连接数字人时若选了「连接后播放预设」，数字人展示页（`knowtalk-chat.html`）会自动把整篇预设讲稿投给 `/human`；此时再在控制台点「开始提问式讲课」，服务端编排器又逐段投喂同一篇讲稿。两条通路写进同一会话的 TTS 队列，于是同一篇讲稿被念两遍。根因是**同一会话存在两个朗读驱动源**，而不是单条链路重复入队。
2. **提问弹窗只在控制台出现**。`#quizPanelHost` 在 `index.html`（控制台）上，学员实际看的是数字人展示页，题目弹在控制台等于学员看不到。
3. **配置受限**：问答对只能手工逐条填，"根据预设文本自动生成问答对"能力缺失；且配置体验与"是否已连接数字人"耦合，使用者希望先配好、连上即用。

## What Changes

- **确立"提问模式独占朗读"的单驱动原则**：启动提问式讲课时，服务端先清空该会话 TTS 队列中的待播内容并作废旧朗读请求，再由编排器投喂第一段；数字人展示页在检测到本会话处于提问模式时，MUST 停止自身的预设演讲且不得再发起，保证同一时刻只有一条朗读流。
- **题目与作答入口迁入展示页右侧对话栏（内联，不用模态弹窗）**：`knowtalk-chat.html` 引入共享的 `quiz-panel.js` 作为状态机，但**不再以全屏模态遮罩弹题**——题目直接作为对话消息出现在右侧「向数字人提问」栏，等待作答时把该栏发送按钮文案改为「回答」，学员在同一输入框作答（文字或 🎤 语音识别出的文本）后点「回答」即走 `POST /api/quiz/answer`；判分结果与反馈也回到对话栏。控制台不再作为学员作答的主界面（保留亦不冲突）。
- **新增"根据预设文本生成问答对"**：新增课堂面接口 `POST /api/quiz/pairs/generate`，接收带可选 `[PPT:N]` 标签的预设文本，按段落调用既有 LLM 出题能力生成「题干 + 参考答案（+ 评分要点 + 页码）」问答对，**不落库、不要求会话存在**，供发起前直接使用。
- **配置可离线**：提问模式的参数量（数量/方式/页码范围）与已填问答对 MUST 可在未连接数字人时编辑并持久化到浏览器本地，连接后直接发起。
- **退出提问模式必须真正停止**：新增 `POST /api/quiz/stop`（课堂面），退出时移除该会话编排器并清空待播朗读。当前"退出"只销毁前端面板、服务端仍继续朗读，是另一个会造成"停不下来/像两段"的缺陷。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `quiz-mode`：补充"单驱动防重复朗读""展示页对话栏内联题目与「回答」按钮""未连接可配置""由预设文本生成问答对"四项可观察约束。

## Impact

- **后端**：`server/quiz_routes.py` 新增 `quiz_pairs_generate` 与路由；`QuizRegistry.start` 在首次推进前调用 `speaker.flush_talk()`（存在则调用）。不修改 `/human`、`/interrupt_talk`、`/is_speaking` 的契约。
- **前端**：`web/index.html` 增加"根据预设文本生成问答对"按钮与配置本地持久化；`web/knowtalk-chat.html` 引入 `quiz-panel.js`（内联模式）、把题目与判分结果写进右侧对话栏、作答时把发送按钮切为「回答」，并在提问模式下停用自身预设演讲。
- **不受影响**：普通模式（未启用提问模式）的朗读时序与切页时机保持本次变更前一致。
