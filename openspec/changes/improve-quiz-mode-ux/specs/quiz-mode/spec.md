# Spec Delta

## ADDED Requirements

### Requirement: 提问模式必须独占朗读，禁止同一会话双段朗读

同一会话在同一时刻 MUST 只有一条朗读驱动源。启动提问式讲课时，服务端 MUST 先清空该会话待播的 TTS 队列并作废旧朗读请求，再投喂第一段教学内容；数字人展示页在检测到本会话处于提问模式时，MUST 停止自身的预设演讲且 MUST NOT 再发起预设演讲。

#### Scenario: 已自动播放预设时启动提问式讲课

- **WHEN** 连接数字人时选了「连接后播放预设」，展示页已开始朗读整篇预设，随后发起提问式讲课
- **THEN** 服务端 MUST 作废并清空展示页那次朗读的待播内容
- **AND** 该会话在同一时刻 MUST NOT 同时存在两条朗读流

#### Scenario: 展示页不重复灌入讲稿

- **WHEN** 展示页轮询到本会话 `in_quiz === true`
- **THEN** 展示页 MUST 停止自身预设演讲
- **AND** MUST NOT 再调用整篇讲稿的一次性投喂

#### Scenario: 普通模式不受影响

- **WHEN** 本会话未启用提问模式
- **THEN** 展示页的预设演讲行为与本次变更前一致

### Requirement: 退出提问模式必须真正停止编排

退出提问模式时，系统 MUST 移除该会话的提问编排器并清空其待播朗读内容，MUST NOT 让编排器在退出后继续投放教学段或提问；该接口 MUST 免口令（课堂面）。

#### Scenario: 退出后不再继续朗读

- **WHEN** 学员或教师退出某会话的提问模式
- **THEN** 该会话的编排器 MUST 被移除，待播朗读 MUST 被清空
- **AND** 后续状态查询 MUST 返回 `in_quiz=false`

#### Scenario: 退出不影响其它会话

- **WHEN** 退出会话 A 的提问模式
- **THEN** 会话 B 的提问编排 MUST 保持不变

### Requirement: 提问必须作用在数字人展示页实际使用的会话上

`/offer` 会为每条 WebRTC 连接创建独立会话，控制台与数字人展示页的 sessionid 并不相同。系统 MUST 让提问编排作用于展示页实际使用的会话：展示页 MUST 公布其会话 id，控制台启动/停止提问时 MUST 以该会话为目标；展示页 MUST 以自己的会话轮询 `/api/quiz/status` 并弹窗。

#### Scenario: 控制台与展示页会话不同

- **WHEN** 控制台连接得到会话 A，展示页 `/offer` 得到会话 B（A≠B）
- **THEN** 启动提问式讲课 MUST 作用在 B 上
- **AND** 展示页轮询 B 时 MUST 看到 `in_quiz=true` 并把题目显示在右侧对话栏

#### Scenario: 展示页尚未连接完成

- **WHEN** 展示页窗口已打开但尚未拿到其会话 id
- **THEN** 控制台 MUST 明确提示等待展示页连接完成
- **AND** MUST NOT 把提问开到控制台自己的会话上

### Requirement: 题目必须内联呈现在展示页右侧对话栏，并由「回答」按钮提交

数字人展示页（`knowtalk-chat.html`）MUST 把当前题目作为对话消息追加到右侧「向数字人提问」对话栏，并在会话进入等待作答时把该栏发送按钮的文案从「提问」改为「回答」、输入提示改为作答提示；提交作答 MUST 走 `POST /api/quiz/answer`，提交后 MUST 立刻把按钮文案恢复为「提问」，避免同一题被重复提交。判分结果与反馈 MUST 同样以对话消息呈现。

展示页 MUST NOT 用全屏模态遮罩呈现题目（不得遮挡数字人画面与课件）。同一道题目在多次状态轮询之间 MUST NOT 被重复追加；提问结束、退出提问模式或连接断开后 MUST 恢复为普通提问状态（按钮文案「提问」、普通输入提示）。

#### Scenario: 等待作答时题目出现在对话栏

- **WHEN** 会话进入 `awaiting_answer` 且存在当前题目
- **THEN** 展示页 MUST 在右侧对话栏追加一条题目消息，含题干原文与题号进度
- **AND** 发送按钮文案 MUST 变为「回答」，输入框提示 MUST 变为作答提示

#### Scenario: 用同一入口作答

- **WHEN** 学员在输入框写答案并点「回答」（或按 Enter）
- **THEN** 客户端 MUST 调用 `POST /api/quiz/answer` 提交该文本，而不是发起聊天/RAG 提问
- **AND** 提交成功后按钮文案 MUST 立刻恢复为「提问」

#### Scenario: 同题不重复追加

- **WHEN** 等待作答期间状态被轮询多次
- **THEN** 对话栏 MUST 只出现该题的一条题干消息

#### Scenario: 状态探测不得因连接流程中断而停摆

- **WHEN** 连接/重连流程中任一环节提前返回、被新一轮连接取代，或连接被复位
- **THEN** 只要页面持有会话 id，展示页 MUST 继续探测提问状态（MUST 有独立的守护机制恢复探测）
- **AND** MUST NOT 出现"提问已开始但页面完全无反应、连状态角标都没有"的情形

#### Scenario: 语音作答复用同一入口

- **WHEN** 学员点 🎤 用语音回答
- **THEN** 识别出的文本 MUST 填入输入框并走「回答」同一条提交路径
- **AND** 服务端 MUST 以该文本走既有判分与反馈路径

#### Scenario: 判分结果回到对话栏

- **WHEN** 会话在作答后进入 `feedback` 阶段
- **THEN** 展示页 MUST 以对话消息呈现判分结果与反馈语

#### Scenario: 结束或断开后恢复普通提问

- **WHEN** 提问模式结束（`in_quiz=false` 或 `stage=finished`）或连接断开
- **THEN** 发送按钮 MUST 恢复为「提问」，输入提示 MUST 恢复为普通提问提示
- **AND** MUST NOT 遗留作答相关的禁用状态

#### Scenario: 题目交付不受阶段影响

- **WHEN** 服务端状态里已有当前题干（无论 `stage` 是 `asking`、`awaiting_answer` 还是其它值）
- **THEN** 展示页 MUST 把题干显示到对话栏
- **AND** 只有 `awaiting_answer` 才 MUST 把发送按钮切成「回答」

#### Scenario: 提问已在运行但暂时没有题干

- **WHEN** 展示页轮询到 `in_quiz=true` 但状态里没有当前题干
- **THEN** 对话栏 MUST 仍按普通提问可用，且状态角标 MUST 显示"等待题目"
- **AND** 一旦状态里出现题干，MUST 立即追加到对话栏

### Requirement: 页面刷新或重连 MUST 续接提问，不得中断课堂

`/offer` 每次都会新建独立 WebRTC 会话。系统 MUST 让提问编排跟着会话迁移：展示页在 `/offer` 时 MUST 告知服务端自己上一轮使用的会话 id；服务端在**该会话已无人观看**（没有活跃 PeerConnection）且有编排器时，MUST 把编排器重新绑定到新会话（保留进度、当前题目、等待作答起点），并 MUST NOT 让旧会话上的编排器在会话消失后继续推进。

判定是否"还有人看" MUST NOT 只看会话对象是否存在：刷新时旧连接已断开，但服务端要等 ICE 判定超时才摘除会话对象；只看会话对象会把刷新误判成"旧页面仍在用"，导致提问不迁移。也 MUST NOT 只看 PeerConnection 状态：刷新后的旧 PC 在服务端常常长时间保持 `connected`，同样会把刷新误判成"仍在用"。展示页 MUST 在卸载时主动声明释放该会话，服务端 MUST 据此判定可迁移；无释放信号时 MUST 在退避重试窗口内持续重试。

#### Scenario: 等待作答时刷新展示页

- **WHEN** 学员在 `awaiting_answer` 阶段刷新数字人展示页，新会话为 B，旧会话 A 的连接已断开
- **THEN** 服务端 MUST 把 A 上的提问编排迁移到 B
- **AND** 展示页轮询 B MUST 看到 `in_quiz=true`、同一道题目与「回答」按钮
- **AND** 学员提交作答 MUST 判分并把反馈念在 B 上

#### Scenario: 旧会话对象仍在但连接已断

- **WHEN** 旧会话对象仍存在于会话表中（ICE 尚未判定超时），但其 PeerConnection 已不是连接状态
- **THEN** 服务端 MUST 视为可迁移，并把提问编排接到新会话上

#### Scenario: 旧会话仍有活跃连接时不迁移

- **WHEN** 旧会话仍有另一块展示页在活跃连接上使用
- **THEN** 系统 MUST NOT 把该会话的提问编排迁走
- **AND** 服务端 MAY 在稍后重试，若那时旧连接已断开则迁移

#### Scenario: 刷新时旧页面主动声明释放

- **WHEN** 展示页被刷新或关闭（`pagehide`），且它持有本页会话 id
- **THEN** 客户端 MUST 通过 `POST /api/quiz/release` 声明该会话已释放
- **AND** 服务端 MUST 据此把该会话判为"无人观看"，即使其 PeerConnection 仍是 `connected`
- **AND** 该会话 id 若重新建立连接，释放标记 MUST 被清除

#### Scenario: 无释放信号时持续重试

- **WHEN** 浏览器未能送出释放信号（进程被杀、网络中断等）
- **THEN** 服务端 MUST 在退避重试窗口内持续尝试迁移，窗口用尽前 MUST NOT 放弃

#### Scenario: 会话消失后暂停推进

- **WHEN** 编排器所在会话已不存在（等待迁移）
- **THEN** 系统 MUST 暂停该编排器的推进，MUST NOT 继续向无人接收的通道投喂内容

#### Scenario: 刷新后不得抢播整篇预设

- **WHEN** 展示页刷新后带着「连接后播放预设」重连
- **THEN** 自动播放预设 MUST 先确认一次提问状态；若本会话处于提问模式则 MUST NOT 播放整篇预设

### Requirement: 连接前即可准备并登记提问

提问模式的参数与问答对 MUST 在未连接数字人时录入、编辑、生成并持久化；此时点击「开始提问式讲课」MUST 把该次配置登记为「待启动」而不是报错，并在数字人展示页连上后自动开始。退出提问模式 MUST 清除该登记，避免下次连接被意外开课。

#### Scenario: 未连接时填好问答对并发起

- **WHEN** 尚未连接数字人，用户填好问答对后点「开始提问式讲课」
- **THEN** 客户端 MUST 保存该配置并提示「展示页连上后自动开始」
- **AND** MUST NOT 因未连接而拒绝或丢弃配置

#### Scenario: 展示页连上后自动开始

- **WHEN** 展示页连上并公布了它自己的会话 id，且存在待启动登记
- **THEN** 客户端 MUST 在该会话上自动发起提问式讲课，且只发起一次

#### Scenario: 控制台刷新不丢登记

- **WHEN** 登记之后刷新了控制台页面
- **THEN** 页面加载 MUST 重新读取登记并继续等待展示页会话

#### Scenario: 陈旧的展示页会话 id 不得导致报错

- **WHEN** 本地保存的展示页会话 id 在服务端已不存在（如服务重启、展示页异常关闭后残留）
- **THEN** 自动发起 MUST NOT 以失败告终：MUST 清掉陈旧 id、保留待启动登记并继续等待
- **AND** 用户界面 MUST 给出「展示页连上后自动开始」类的说明，而不是错误提示

#### Scenario: 展示页新开时不得沿用上次的会话 id

- **WHEN** 展示页重新打开（加载）时本地仍存有上一次的会话 id
- **THEN** 页面 MUST 先清除该值，连接成功后再写入本次会话 id

#### Scenario: 退出提问模式清除登记

- **WHEN** 用户点「退出提问模式」
- **THEN** 待启动登记 MUST 被清除

### Requirement: 未连接数字人时可配置提问模式

提问模式的参数量（数量/方式/页码范围）与已填问答对 MUST 可在未连接数字人时编辑，并 MUST 能持久化到浏览器本地、在页面重载后回填。配置本身不需要任何连接；用户只需配置，发起与开课由系统在展示页连上后自动完成。

#### Scenario: 未连接时编辑并保存配置

- **WHEN** 尚未连接任何数字人，用户修改提问数量/方式/页码范围或填写问答对
- **THEN** 这些配置 MUST 可被保存并在刷新页面后回填

#### Scenario: 未连接时发起不报错

- **WHEN** 未连接数字人时点击「开始提问式讲课」
- **THEN** 客户端 MUST 把该次配置登记为待启动并说明"展示页连上后自动开始"
- **AND** MUST NOT 以"请先连接数字人"为由拒绝

### Requirement: 问答对可由预设文本自动生成

系统 MUST 提供课堂面接口 `POST /api/quiz/pairs/generate`，依据给定的预设文本（可含 `[PPT:N]`/`[slide:N]` 标签）生成「题干 + 参考答案（+ 评分要点 + 页码）」问答对。该接口 MUST NOT 要求会话存在，MUST NOT 写入题库；生成失败时 MUST 返回明确业务错误。

#### Scenario: 按段落生成问答对

- **WHEN** 提交含多段 `[PPT:N]` 标签的预设文本
- **THEN** 系统 MUST 逐段调用出题能力，并为每条问答对标注其所属幻灯片编号
- **AND** 结果 MUST NOT 落库

#### Scenario: 未配置 LLM 时明确报错

- **WHEN** 未配置可用的对话模型
- **THEN** 接口 MUST 返回明确的业务错误，提示去配置 LLM，而非返回空结果或崩溃

#### Scenario: 缺少文本被拒绝

- **WHEN** 请求未提供 `text` 或文本为空
- **THEN** 接口 MUST 返回业务错误，不发起任何出题调用

### Requirement: 判分必须由大模型完成，且判分后继续讲授剩余内容

学员作答后 MUST 由**对话大模型**（复用 `llm.api_key` / `llm.base_url` / `llm.model`）给出三档判分结论（correct / partial / missing）与一句可朗读的反馈；判分失败 MUST 降级并记录（不得让课堂停住），且降级 MUST 在界面可辨识。

演练必须是一堂课而不是一串孤立的题：提问 MUST 带着讲稿一起提交，编排器按「讲授段 →（到提问点）提问 → 等作答 → 判分反馈 → 继续讲授剩余段落」的顺序推进，讲稿里的 `[PPT:N]` 标签 MUST 在对应段落播放时切页。客户端在「预设文本」为空时 MUST 回退使用「连接后播放预设」选中的那份文本；两者都为空时 MUST 明确告知"本次只提问、不讲授"，不得静默变成纯提问。

展示页在控制台已登记待启动提问（`zhike_quiz_pending`）时 MUST NOT 自行播放整篇预设，避免与编排器的讲授重复朗读。

#### Scenario: 判分由大模型给出

- **WHEN** 学员提交作答且已配置可用的对话模型
- **THEN** 判分 MUST 调用该模型并返回 `verdict` 与 `feedback`
- **AND** 反馈 MUST 被朗读，且 MUST NOT 出现 `degraded=true`

#### Scenario: 判分不可用时的降级

- **WHEN** 未配置模型或调用失败
- **THEN** 系统 MUST 仍给出降级反馈并继续课堂，同时 MUST 记录明确的失败原因

#### Scenario: 判分后继续讲授剩余 PPT

- **WHEN** 学员回答完某次提问且讲稿中仍有后续段落
- **THEN** 系统 MUST 在反馈之后继续投喂剩余教学段，并按段落的 `[PPT:N]` 切页
- **AND** 全部段落讲完后才结束

#### Scenario: 讲稿为空时必须提示只提问

- **WHEN** 「预设文本」与所选预设都没有内容却仍发起提问式讲课
- **THEN** 客户端 MUST 明确说明本次只提问、不讲授剩余内容

### Requirement: 课堂结束必须给出总评分，展示页 3 秒后收起对话栏

一次提问式讲课结束后，系统 MUST 依据本次会话的问答记录给出百分制总评分，MUST 同时给出题数明细（共几题、答对、部分正确、未答），并 MUST 让数字人把这段评分念出来。

计分口径 MUST 明确且可测：完全正确 = 100 分、部分正确 = 60 分、未覆盖 或 未作答 = 0 分；总分为各题得分的算术平均（四舍五入取整）。没有作答记录时 MUST NOT 给出评分，也 MUST NOT 朗读评分。

展示页 MUST 在评分消息呈现后等待 3 秒再自动收起右侧对话栏；MUST NOT 在课堂进行中收起，MUST NOT 因刷新页面而重复收起。

系统 MUST 提供 `GET /api/quiz/report?sessionid=` 供展示页/控制台补取评分，编排器已销毁时也必须能按该会话的历史记录算出同样的结果。

#### Scenario: 全部答对

- **WHEN** 本次课堂 2 道题均判定为 correct
- **THEN** 评分 MUST 为 100 分，明细 MUST 显示答对 2 题

#### Scenario: 混合结果

- **WHEN** 本次课堂 2 道题分别为 correct 与 partial
- **THEN** 评分 MUST 为 80 分

#### Scenario: 有未作答的题

- **WHEN** 本次课堂 2 道题中 1 题超时未作答、另 1 题 correct
- **THEN** 评分 MUST 为 50 分，明细 MUST 显示未答 1 题

#### Scenario: 评分被念出来并收起对话栏

- **WHEN** 课堂结束且存在作答记录
- **THEN** 数字人 MUST 朗读评分与题数明细
- **AND** 展示页 MUST 显示同一条评分消息，并在 3 秒后自动收起对话栏

#### Scenario: 没有任何作答记录

- **WHEN** 课堂结束时没有任何作答记录
- **THEN** 系统 MUST NOT 给出评分或朗读评分
