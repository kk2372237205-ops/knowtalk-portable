# Design

## 为什么是独立页，不是首页内的分区

首页现在的任务是「说服」：让人在两分钟内明白讲稿即指令、提问按页码触发。控制台的任务是「操作」。两件事都需要占满一屏，放在同一页只能互相压缩。

改成独立页后还有三个直接收益：工作台可以有自己的地址（可收藏、可分享给同事）、首页滚动长度从 6 屏回到 5 屏、控制台不再被 680px 单栏宽度约束。

代价是主脚本要搬家。经核对，主脚本对首页的唯一依赖是 `homeStatusBanner`（错误提示条，且已判空处理），`hpAt`/`hpPageNo` 等演示面板元素全部在第二个脚本块里。因此搬迁风险可控。

## 布局

```
┌─────────────────────────────────────────────────┐
│ 知课   返回首页                          设置    │  ← 静默条，与正文同一条上边线
│ ─────────────────────────────────────────────── │
│ 开播          开始你的一堂课                     │
│ 讲稿          选好形象与声音，一键连接…           │
│ 提问                                            │
│                ┌───────────────────────────┐    │
│                │  数字人连接                │    │
│ 形象生成       │  [Avatar] [音频] [文本]   │    │
│ 课程知识库     │  [开始连接]               │    │
│ 管理后台       └───────────────────────────┘    │
│ 参数设置                                        │
└─────────────────────────────────────────────────┘
```

- 左栏固定 232px，`position: sticky; top: 0; height: 100vh`，自身可滚。
- 右栏 `min-width: 0`，避免 `col-*` 里的长 select 撑破。
- 面板切换用 `hidden` 属性而非 `display:none` 内联样式，便于用 `[hidden]` 统一覆盖 Bootstrap 的 `display` 规则。

## 选中态为什么不用强调色块

首页的按钮是蓝墨水实心、链接是蓝墨水文字。若导航选中态用蓝墨水底色，左栏会出现一块面积不小的饱和色，与首页「一个字都不抢」的语气相反。改为：选中项背景 `--hp-surface`（纸面深一档）、文字墨色、字重 500；未选中 muted、字重 400。选中感来自「纸面被按下去一点」，不来自颜色。

## hash 而不是 query

`#quiz` 不触发服务端请求，静态服务无需任何路由配置；`?panel=quiz` 会让每次切换都产生一次页面级请求，且本地静态服务对未知 query 的行为依赖实现，不如 hash 确定。

监听 `hashchange` 一个事件即可同时覆盖「点击导航」「浏览器前进后退」「手改地址栏」三种来源——不需要额外监听 `popstate`（`popstate` 在 hash 变化时也会触发，两者同时监听会导致重复渲染）。

## 窄屏降级

900px 以下，左栏的纵向列表变成顶部横排的切换条（三个切换项并排，指路链接收进页尾）。此时 `sticky` 改为 `static`，`height: 100vh` 解除，避免在手机上占据整屏。

## 迁移中的既有缺陷

原内联样式里 `#mainStatus { color: var(--page-muted); }` 引用了从未定义的 `--page-muted`，该声明一直无效（文字继承默认色）。迁移时改为 `var(--muted)`，属修复而非行为变更。
