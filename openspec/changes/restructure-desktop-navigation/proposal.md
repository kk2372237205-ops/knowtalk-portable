# 桌面端导航按使用模式重构

## 为什么

侧栏现在是 14 个平级入口，按「功能模块」分组，而不是按「谁在什么时候用」。
真正拿它上课的老师看到的是这样三个分组：实时讲解 / 资源与管理 / 全息舱。
问题有四处：

1. **同一件事有两个入口**：`形象`（选形象）在「实时讲解」，`形象生成` 在
   「资源与管理」，中间隔着四个页面，而哪个都不是完整答案。
2. **「素材与设置」名不副实**：这一页里只有四张设置卡片，没有任何「素材」；
   更糟的是顶栏还有一个「设置」按钮也跳这一页——同一页两个名字。
3. **两个分组名互为同义词**：「资源与管理」对「素材与设置」，
   资源≈素材、管理≈设置，没人能从名字判断该点哪个。
4. **线上讲课的老师要翻越一堆展项配置**：他是备课上课，不是布置展厅，
   但唤醒词、菜单库、待机迎宾、问答记录和讲稿排在同一列里。

根子是分组维度选错了。这个桌面端有两类使用者、两条动线：老师线上讲课，
运营线下布展。它们的交集只有「开播」和「形象与设置」，其余互不相干。

## 做什么

1. **侧栏顶部加模式切换**（演讲模式 / 展览模式），同一时刻只渲染一套导航：
   - 演讲模式：备课（讲稿 / 提问 / 课件 / 课程知识库）+ 上课（开播）
   - 展览模式：全息舱（唤醒与打断 / 菜单库 / 待机与迎宾 / 问答记录）+ 启动（开播）
   - 通用（两种模式都显示）：形象与设置 / 管理后台 / 系统状态
2. **形象库、形象生成、语音与音频合成一页**「形象与设置」，页内三栏切换。
   子页通过 `embedded=True` 隐藏各自的大标题，避免与宿主标题重复。
3. **切换模式记住各自上次停留的页**，切回来不用重新找。
4. **收紧导航行高与分组间距**：1.5 倍缩放下原 40px 行高会让 8 项导航
   溢出 222px，压到 34px 并缩短分组留白，1280×820 窗口内可完整显示。

## 影响

- `desktop_app.py`：新增 `StudioPage`；`MainPage` 的 `NAV_MAIN/NAV_SUB/NAV_KIOSK`
  换成 `MODE_TABS / MODE_NAV / COMMON_NAV`；`_show_page` 增加宿主页与分栏切换；
  `AvatarMgrPage / GenAvatarPage / SettingsPage` 增加 `embedded` 参数。
- 页 key 保持兼容：`avatar` / `gen` / `material` 仍然可用（`material` 映射到
  「语音与音频」分栏），线程事件泵里 `app._main.settings_page.xxx` 这类调用不受影响。
- 不改任何后端接口、不改页面内部业务逻辑。
