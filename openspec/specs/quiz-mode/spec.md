# quiz-mode Specification

## Purpose
在讲课过程中插入可配置或随机的提问点，让数字人停下讲课与幻灯片切换、抛出问题、接收文字或语音作答、由 LLM 判定并给出反馈后继续讲课；未启用时完全保持原有的连续讲授行为。本变更补充客户端**呈现方式**的可观察约束。

## Requirements

### Requirement: 提问在客户端必须以模态弹窗呈现

客户端 MUST 在题目进入等待作答或判分阶段时，以模态弹窗（覆盖层 + 居中卡片）呈现题目与作答区；未处于这两个阶段（讲授、念题干、未启用提问模式、已结束）时 MUST NOT 显示任何弹窗。弹窗 MUST NOT 因点击遮罩而关闭，只能由提交、跳过或结束触发卸载。

#### Scenario: 等待作答时弹出

- **WHEN** 会话进入等待作答阶段且存在当前题目
- **THEN** 客户端 MUST 显示模态弹窗并写出题干原文
- **AND** MUST 提供作答输入与提交入口

#### Scenario: 讲授阶段不弹窗

- **WHEN** 会话处于讲授或念题干阶段
- **THEN** 客户端 MUST NOT 显示提问弹窗
- **AND** MUST NOT 在页面上留下空卡片

#### Scenario: 结束时收起

- **WHEN** 提问式讲课结束或退出提问模式
- **THEN** 客户端 MUST 移除弹窗且不遗留定时器

### Requirement: 弹窗必须同时提供语音与文字两种作答入口

提问弹窗 MUST 同时提供文字作答与语音作答两种入口，且 MUST 允许学员在两者之间选择。两种作答 MUST 走与既有提问模式一致的接口与判分路径（文字 `/api/quiz/answer`、语音 `/api/quiz/answer/audio` 转写后判分）。

#### Scenario: 可切换作答方式

- **WHEN** 弹窗处于等待作答状态
- **THEN** 客户端 MUST 同时呈现文字输入与语音录入入口
- **AND** 学员 MUST 能选择其中一种方式提交

#### Scenario: 语音作答走原路径

- **WHEN** 学员选择语音作答并提交可识别音频
- **THEN** 服务端 MUST 以转写文本走既有判分与反馈路径
- **AND** MUST NOT 因前端切换作答方式而改变后端行为
