# repository-hygiene Specification

## Purpose
定义 KnowTalk 仓库中哪些文件允许进入版本库、忽略规则如何编写、依赖如何声明、启动与容器化入口如何保持可复现，以及敏感信息如何与仓库隔离，使仓库内容可长期维护且不随运行而膨胀。

## Requirements

### Requirement: 可再生的运行产物不得进入版本库

日志、运行截图、缓存目录、回收目录、字节码目录、虚拟环境、模型权重、上传临时文件等可在本地重新生成的内容 MUST NOT 被纳入版本库，MUST NOT 长期留在工作区目录中。

#### Scenario: 服务运行后产生日志与缓存

- **WHEN** 本地启动服务并产生日志、`__pycache__/`、`.numba_cache/`、上传临时文件
- **THEN** 这些内容不会出现在 `git status` 的待提交清单中
- **AND** 工作区中不保留体积明显的运行残留

#### Scenario: 清理已有的运行产物

- **WHEN** 仓库根目录存在日志文件、调试截图或清理回收目录
- **THEN** 这些内容被删除
- **AND** 删除后再次运行服务不会因此缺少任何源码或配置

### Requirement: 忽略规则必须使用目录锚定且不得误伤源码

`.gitignore` 中用于忽略目录的模式 MUST 以斜杠结尾或使用明确的路径前缀，MUST NOT 使用会匹配任意同名路径的裸目录名。用于忽略调试产物的通配模式 MUST NOT 匹配合法的源码文件。

#### Scenario: 忽略数据目录

- **WHEN** `.gitignore` 需要忽略项目根下的数据目录
- **THEN** 规则使用 `/data/` 这样的锚定形式
- **AND** 仓库中任何其它位置名为 `data` 的目录不会被误忽略

#### Scenario: 通配规则匹配到源码

- **WHEN** 存在形如 `_*.py` 的忽略规则
- **THEN** 该规则被收窄或移除，使合法的下划线开头源文件仍可被跟踪
- **AND** 通过实际创建一个候选文件并检查 `git check-ignore` 验证结论

### Requirement: 忽略规则不得包含重复或相互矛盾的条目

`.gitignore` MUST NOT 包含重复的模式。同一目标目录 MUST 只被声明一次。

#### Scenario: 审查现有忽略规则

- **WHEN** 逐行检查 `.gitignore`
- **THEN** 不存在两次出现的相同模式
- **AND** 不存在对同一目录的重复声明

#### Scenario: 新增忽略规则

- **WHEN** 需要新增一条忽略规则
- **THEN** 先确认该模式或其等价形式尚未存在
- **AND** 若已存在则复用现有规则而不是追加重复项

### Requirement: 大体积二进制资源必须通过 Git LFS 管理

模型权重与其它超过常规代码体量的二进制资源（`.pth`、`.pt`、`.onnx`、`.safetensors`、`.pkl`、`.bin` 等）MUST 由 `.gitattributes` 的 LFS 规则管理，MUST NOT 以普通对象直接提交。

#### Scenario: 新增一个模型权重文件

- **WHEN** 把一个 `.pth` 或 `.onnx` 模型加入仓库
- **THEN** 该文件在 Git 中表现为 LFS 指针
- **AND** `git lfs ls-files` 能列出该文件

#### Scenario: 检查二进制类型覆盖

- **WHEN** 仓库中存在未被 LFS 覆盖的大体积二进制扩展名
- **THEN** `.gitattributes` 补充对应规则
- **AND** 已误提交的普通对象按需迁移到 LFS

### Requirement: 敏感信息只允许以示例文件入库

真实密钥、令牌、口令 MUST NOT 出现在任何被跟踪的文件中。仓库 MUST 只跟踪 `.env.example`、`.env.rag.example` 这类占位示例；真实配置文件 MUST 被忽略规则排除。示例文件 MUST NOT 包含真实凭据或他人的服务地址。

#### Scenario: 提交环境变量配置

- **WHEN** 需要新增一个环境变量
- **THEN** 只在示例文件中加入占位值
- **AND** 真实值仅存在于被忽略的本地文件中

#### Scenario: 审查被跟踪文件

- **WHEN** 对仓库执行一次被跟踪文件清单检查
- **THEN** 清单中不包含真实的环境变量文件、日志、虚拟环境或包含密钥的本地工具配置

### Requirement: 工作区中出现的明文密钥必须被轮换

当工作区（即使未被跟踪）发现明文密钥时，MUST 按已泄露处理：先轮换该密钥，再把它移到被忽略的本地配置中。MUST NOT 仅依赖忽略规则就认为安全。

#### Scenario: 本地工具配置包含明文密钥

- **WHEN** 发现 `opencode.json` 这类本地配置文件含有真实 API Key
- **THEN** 该密钥被吊销并重新签发
- **AND** 新密钥只保存在被忽略的本地文件中

### Requirement: 依赖必须被完整声明并有统一的版本策略

清单文件 MUST 覆盖代码实际导入的所有第三方包。多个清单 MUST 对同一个包使用一致的版本策略，MUST NOT 出现同一包在不同清单中互相冲突的版本约束。

#### Scenario: 代码导入了一个未声明的包

- **WHEN** 源码中导入了一个在清单中缺失的包
- **THEN** 该包被加入对应清单
- **AND** 在干净环境中按清单安装后可以启动服务

#### Scenario: 同一包出现冲突约束

- **WHEN** 同一包在两个清单中分别被要求为不同版本
- **THEN** 版本约束被协调为彼此兼容的取值
- **AND** 记录选择该取值的理由

#### Scenario: 评估版本锁定程度

- **WHEN** 审查清单的版本约束
- **THEN** 清单采用统一策略（全部锁定、全部设下界、或明确分层说明）
- **AND** 不会在同一份清单中无说明地混用多种策略

### Requirement: 启动脚本必须使用项目环境并校验真实依赖

本地一键启动脚本 MUST 使用项目自身的解释器环境，MUST NOT 依赖全局 `python`。其依赖校验 MUST 覆盖启动主流程实际需要的关键包，而不是只检查少数几个包就宣告环境就绪。

#### Scenario: 在干净机器上执行一键启动

- **WHEN** 运行一键启动脚本
- **THEN** 脚本使用项目环境中的解释器
- **AND** 缺失关键依赖时给出明确的可操作提示，而不是继续启动后失败

#### Scenario: 可选组件缺失

- **WHEN** 可选组件（如 RAG 独立环境）不存在
- **THEN** 脚本给出提示并继续启动主服务
- **AND** 不会因为可选组件缺失而中止

### Requirement: 容器镜像必须能从干净上下文构建

`Dockerfile` MUST 以可复现的方式描述镜像：源码复制路径 MUST 位于构建上下文内，依赖安装 MUST 发生在目标环境中，启动命令 MUST 能拉起实际服务。MUST NOT 保留上游遗留的、在本仓库中无效的步骤。

#### Scenario: 构建镜像

- **WHEN** 在仓库根目录执行镜像构建
- **THEN** 构建成功并包含应用源码与依赖
- **AND** 容器启动后主服务监听到配置的端口

#### Scenario: 镜像中残留上游遗留步骤

- **WHEN** `Dockerfile` 中存在不生效的环境激活步骤或指向构建上下文之外的复制路径
- **THEN** 这些步骤被修正或删除
- **AND** 镜像描述与实际部署方式一致

### Requirement: 仓库根目录只保留项目资产

仓库根目录 MUST 只包含入口源码、配置、依赖清单、文档与许可等长期资产。MUST NOT 堆积调试脚本、临时输出、截图或与项目无关的本地文件。

#### Scenario: 添加一个临时调试文件

- **WHEN** 开发过程中产生一次性的调试脚本或输出
- **THEN** 它要么被放入被忽略的临时位置，要么在提交前删除
- **AND** 根目录文件清单保持可解释

#### Scenario: 审查根目录清单

- **WHEN** 逐项检查仓库根目录的文件与目录
- **THEN** 每一项都能归入源码、配置、文档或许可中的一类
- **AND** 无法归类的项被删除或移入忽略范围
