# speech-synthesis Specification

## Purpose
定义语音合成引擎的统一契约：引擎如何选择、离线可用性如何保证、合成失败如何可见、回退如何工作，以及产出必须满足的采样率与分块约定，使外部语音服务不可用时课堂仍能发声且原因可查。

## Requirements

### Requirement: TTS 引擎必须可从统一入口选择

服务 MUST 通过统一参数选择 TTS 引擎，并在启动时加载对应插件。选择未注册的引擎名时 MUST 明确报告可用引擎清单，MUST NOT 静默退化为不发声。

#### Scenario: 选择已注册引擎

- **WHEN** 启动时指定一个已注册的引擎名
- **THEN** 该引擎 MUST 被加载并用于后续合成

#### Scenario: 选择未注册的引擎

- **WHEN** 启动时指定的引擎名未注册
- **THEN** 服务 MUST 明确报告该名称未注册并列出可用引擎
- **AND** MUST NOT 静默地让会话不发声

### Requirement: 必须提供不依赖外部网络的合成引擎

服务 MUST 提供一个使用操作系统自带语音能力、完全离线工作的 TTS 引擎。该引擎 MUST NOT 依赖任何外部网络服务。

#### Scenario: 断网环境下合成

- **WHEN** 在无外部网络的环境中使用该引擎合成文本
- **THEN** 合成 MUST 成功并产出音频
- **AND** MUST NOT 产生任何对外网络请求

#### Scenario: 引擎不可用的平台

- **WHEN** 在缺少该系统语音能力的平台上选择该引擎
- **THEN** 服务 MUST 明确报告该平台不支持
- **AND** MUST NOT 抛出未捕获异常导致启动或会话中断

### Requirement: 系统语音的可用性必须被判定并报告

使用系统语音的引擎 MUST 在选择语音前判定其可用性，并在没有可用语音或没有目标语言的语音时明确报告。MUST NOT 在无可用语音时静默产出空音频。

#### Scenario: 存在目标语言语音

- **WHEN** 系统中存在目标语言（中文）的语音
- **THEN** 引擎 MUST 选用该语音并完成合成

#### Scenario: 缺少目标语言语音

- **WHEN** 系统中没有任何目标语言的可用语音
- **THEN** 引擎 MUST 明确报告缺少目标语言语音
- **AND** MUST NOT 返回空音频当作成功

### Requirement: 合成失败必须可见

任何 TTS 引擎在合成产出为空或合成过程出错时 MUST 产生可被上层察觉的失败结果，MUST NOT 仅记录日志后静默返回。失败结果 MUST 附带可操作的排查提示。

#### Scenario: 依赖的外部服务不可用

- **WHEN** 某引擎依赖的外部服务返回错误导致没有产出音频
- **THEN** 上层 MUST 能察觉到该次合成失败
- **AND** 提示 MUST 指出该引擎依赖外部服务并给出改用离线引擎的建议

#### Scenario: 不得静默返回

- **WHEN** 一次合成没有产出任何音频
- **THEN** 该次合成 MUST NOT 被当作成功
- **AND** MUST NOT 只写日志就返回

### Requirement: 合成失败时可回退到备用引擎

服务 MUST 支持配置一个备用引擎。被选引擎合成失败时，若备用引擎可用，服务 MUST 用同一段文本与同一组参数改用备用引擎重试一次，并 MUST 报告发生了回退。

#### Scenario: 主引擎失败后回退成功

- **WHEN** 主引擎合成失败且配置的备用引擎可用
- **THEN** 服务 MUST 用备用引擎重新合成同一段文本
- **AND** MUST 产生音频，并报告本次发生了回退

#### Scenario: 未配置备用引擎

- **WHEN** 主引擎合成失败且未配置备用引擎
- **THEN** 服务 MUST 明确报告失败与原因
- **AND** MUST NOT 静默丢弃该段文本

### Requirement: 回退链不得循环

回退 MUST 至多发生一次，备用引擎自身失败时 MUST NOT 回退回原引擎，也 MUST NOT 形成任何环。

#### Scenario: 备用引擎同样失败

- **WHEN** 主引擎与备用引擎都合成失败
- **THEN** 服务 MUST 报告两次失败
- **AND** MUST 终止该次合成，MUST NOT 继续尝试任何引擎

#### Scenario: 备用引擎配置为主引擎本身

- **WHEN** 备用引擎被配置成与主引擎相同的名称
- **THEN** 服务 MUST 识别该配置无意义并明确报告
- **AND** MUST NOT 重复调用同一引擎

### Requirement: 合成产出必须满足既有的采样率与分块约定

引擎产出的音频 MUST 为 16 kHz 单声道，并按既有的固定帧长切分为音频帧；不同引擎之间 MUST NOT 改变帧长、通道数或采样率，以免破坏下游消费。

#### Scenario: 换用离线引擎后下游不变

- **WHEN** 从依赖外部服务的引擎切换到离线引擎
- **THEN** 产出的音频帧长度、通道数与采样率 MUST 与切换前一致

#### Scenario: 源音频采样率不同

- **WHEN** 引擎合成出的音频采样率不是 16 kHz
- **THEN** 服务 MUST 重采样为 16 kHz
- **AND** MUST 只取单声道

### Requirement: 合成失败必须限定在单次请求内

一次合成失败 MUST NOT 影响其它会话或后续的合成请求；服务 MUST 在失败后仍能继续处理新的合成请求。

#### Scenario: 失败后仍可继续

- **WHEN** 某次合成失败并被报告
- **THEN** 随后提交的合成请求 MUST 能被正常处理

#### Scenario: 其它会话不受影响

- **WHEN** 一个会话的合成失败
- **THEN** 其它会话的合成 MUST NOT 受到影响

### Requirement: 新引擎必须可从运行期设置与命令行选择

新引擎 MUST 出现在运行的引擎枚举中，MUST 能通过命令行参数与运行期设置选定，且标注其生效时机。

#### Scenario: 通过设置切换引擎

- **WHEN** 在设置中把 TTS 引擎改为离线引擎
- **THEN** 此后新建的会话 MUST 使用该引擎

#### Scenario: 命令行指定

- **WHEN** 启动时通过命令行参数指定该引擎
- **THEN** 服务 MUST 使用该引擎启动

### Requirement: 离线引擎的音质取舍必须成文

文档 MUST 说明离线引擎与依赖外部服务的引擎在音质与可用性上的取舍，MUST 给出在两者间切换的方法，MUST NOT 让使用者误以为两者音质相当。

#### Scenario: 查阅文档

- **WHEN** 查阅 TTS 相关文档
- **THEN** MUST 能查到离线引擎的音质取舍说明
- **AND** MUST 能查到切换引擎的方法

### Requirement: 开箱即可发声的默认兜底

在提供系统离线语音能力的平台上，未显式配置备用引擎时，服务 MUST 默认启用该平台的离线引擎作为兜底。显式配置 MUST 优先于该默认值，且 MUST 能关闭兜底。

#### Scenario: 未做任何配置即启动

- **WHEN** 在提供系统离线语音能力的平台上，未通过命令行或运行期设置配置备用引擎就启动服务
- **THEN** 生效的备用引擎 MUST 是该平台的离线引擎
- **AND** 主引擎失败时 MUST 自动改用该离线引擎并产出音频

#### Scenario: 显式关闭兜底

- **WHEN** 使用者显式把备用引擎设为"不回退"
- **THEN** 服务 MUST NOT 在失败时改用其它引擎
- **AND** MUST 明确报告失败与原因

#### Scenario: 平台不提供离线语音能力

- **WHEN** 运行平台不提供系统离线语音能力
- **THEN** 生效的备用引擎 MUST NOT 指向该离线引擎
- **AND** 该平台的合成行为 MUST 与未引入本要求时一致

### Requirement: 主引擎反复失败时必须在会话内短路，且不得丢弃文本

主引擎在一个会话内被反复证实失败、且备用引擎已成功接管后，本会话后续合成 MUST 直接使用备用引擎，不再重复等待同一个失败。短路 MUST NOT 导致文本被拒绝、跳过或丢弃；新会话 MUST 重新尝试主引擎。

#### Scenario: 反复失败后短路

- **WHEN** 主引擎在同一会话内连续多次合成失败，且每次失败都已由备用引擎成功接管
- **THEN** 该会话后续的合成 MUST 直接使用备用引擎
- **AND** MUST NOT 再次调用已被证实失败的主引擎

#### Scenario: 单次失败不短路

- **WHEN** 主引擎只失败过一次，随后的合成由主引擎成功完成
- **THEN** 服务 MUST NOT 进入短路状态
- **AND** 后续合成 MUST 继续优先使用主引擎

#### Scenario: 短路状态下文本仍被合成

- **WHEN** 会话处于短路状态并提交了新的文本
- **THEN** 该文本 MUST 仍被合成并产出音频
- **AND** MUST NOT 被拒绝、跳过或丢弃

#### Scenario: 没有可接管的备用引擎

- **WHEN** 主引擎失败且没有任何可用的备用引擎
- **THEN** 服务 MUST NOT 进入短路状态
- **AND** 后续请求 MUST 继续尝试主引擎

#### Scenario: 备用引擎失效时解除短路

- **WHEN** 会话处于短路状态，而备用引擎在后续合成中失败
- **THEN** 服务 MUST 解除短路状态
- **AND** 下一次合成 MUST 重新尝试主引擎

#### Scenario: 新会话重新尝试主引擎

- **WHEN** 建立一个新的会话
- **THEN** 该会话 MUST 重新尝试主引擎，而不是沿用上一个会话的短路状态
